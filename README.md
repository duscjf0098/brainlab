# 두뇌실험실

인지 능력, 정서 지능, 성격, 연애 애착 유형, 연애 스타일, 진로 흥미 유형을 측정하는 자기평가 웹사이트. 서버 없이 정적 파일만으로 동작한다.

## 실행

```
node serve.cjs
```

브라우저에서 http://localhost:5173 을 연다. `index.html`을 더블클릭해도 동작한다.

## 구조

- `index.html` 진입점. 스크립트 로드 순서가 중요하다 (util → tests → card → app).
- `css/style.css` 미니멀 연구소 테마. 색은 `:root` 토큰으로 관리하고 다크 모드를 자동 지원한다.
- `js/util.js` 난수(seeded RNG), HTML 이스케이프, 저장소 유틸.
- `js/tests/*.js` 검사 정의. 각 파일은 `BL.tests.<id> = { build(), score(answers, items), ... }` 를 등록한다. 검사 정의에 `related: [{ id, why }]`를 두면 결과 화면 맨 아래에 그 검사로 가는 "이어서 해 보기" 카드가 붙는다(애착 ↔ 연애 스타일).
- `js/card.js` 결과 카드 PNG 생성(1080×1350), 저장, 공유.
- `js/app.js` 해시 라우팅, 문항 렌더러(choice / likert / digitspan / reaction / section), 결과·기록·안내 화면.

## 라우트

- `#/` 홈
- `#/test/<id>` 소개 · `#/run/<id>` 진행 · `#/result/<id>/<n>` 결과
- `#/preview/<id>` 무작위 응답으로 결과 화면만 미리보기 (디자인 작업용). 인지 검사는 `#/preview/cognitive/quick` 으로 빠른 검사 결과도 볼 수 있다.
- `#/history` 내 기록 · `#/about` 안내

검사 id: `cognitive`, `eq`, `personality`, `attachment`, `interest`, `love` (홈 카드 순서)

## 글 톤과 설명 블록

- 사용자에게 보이는 설명은 쉬운 말, 해요체로 쓴다(문항·정답 해설은 제외). 전문 용어는 꼭 필요할 때 한 번만 쓰고 바로 풀어 준다.
- 영역·갈래·축마다 `what`(무엇을 재나)과 `where`(일상에서 어디에 쓰이고 어떤 영향을 주나)를 둔다. 각 검사 객체의 `explain` 배열이 **결과 화면**의 "무엇을 잰 걸까요, 어디에 쓰일까요" 블록이 된다(소개 페이지에는 두지 않는다; 결과에 나온 영역만 표시). 인지 과제 18개는 `TASKS[k].where`가 과제 시작 카드에 "일상에서" 줄로 나온다.

## 문항 갤러리 (검수용)

- `#/gallery/<과제 키>/<단계 또는 all>[/<단계당 개수>]` — 예: `#/gallery/matrix/all`, `#/gallery/weights/5/3`. 생성 문항을 연습 모드(타이머 없음)로 쭉 그려 주고 정답 보기를 초록 테두리로 표시한다. 저장되지 않는다. 과제 키: matrix, figAnalogy, series, sequence, weights, rotation (analogy·vocab·logic·similar도 됨).
- 도형 그리기 규칙(2026-10-15 점검): 마름모 틀은 안쪽이 좁아 도형 3~4개와 겹치므로 틀은 none·square·circle·hexagon만 쓴다. 모서리 점은 (13,13)·(87,87) 등 셀 구석에 두어 둥근·육각 틀과 큰 도형 4개에 겹치지 않는다. 저울 보기 접시는 7개까지 올라가므로 접시를 넓게(10~110) 그린다.

## 문구 검증

- `scratchpad/text.cjs <루트>`: 생성 문항 수천 개와 모든 결과 문장(검사·모드별 무작위 응답)을 만들어, 조사 자리표시자("을(를)", "이(가)", "(으)로", "와(과)")·딱딱한 합니다체("~니다", 문항 속 "아니다"는 제외)·깨진 값(undefined/NaN)이 없는지 확인한다. 조사는 항상 `U.josa(단어, 받침 있을 때, 없을 때)`로 붙인다. 불러오는 파일 목록이 고정이라 새 검사 파일을 더하면 목록에 넣어 돌린다.

## 정답 검증

- `scratchpad/audit.cjs <루트> [반복]`: 생성 문항(행렬·유추·계열·수열·저울·회전)을 단계별로 수천 개 만들어, 보이는 칸·저울·도형만으로 다시 계산한 정답이 보기 중 정확히 하나인지 확인한다. 저울은 1~9 범위의 모든 무게 조합 중 주어진 저울과 맞는 조합 전부에서 정답만 평형이어야 하고, 2×2 집합 논리는 예시 행에 맞는 모든 (연산, K′) 가설이 같은 답을 내야 한다(`kUnique`).
- 2026-10-15에 잡은 오류: (1) 2×2 집합 논리에서 숨은 K가 예시 왼쪽 칸과 겹치면 "보이는 변화"로 추론한 답이 정답과 달라졌다 → `logicK`가 가설 전수 검사를 통과하는 조합만 쓴다. (2) 저울 추론 4~5단계에서 한쪽에 2개를 올릴 때 반대쪽에 6개 이상이 필요하면 접시 한도(5개) 때문에 엉뚱한 저울이 그려졌다 → 2개 올리기는 2·무게 ≤ 5일 때만. (3) 수열 `primesSkip`의 2, 5, 11, 17, 23은 "+6"으로도 읽혀 모호 → `altNext`에 뒤쪽 세 차이가 같은 경우를 추가.
- `scratchpad/verbal.cjs <루트> [반복]`: 언어 4과제 문항 풀 검사. 풀마다 35개 이상·단계마다 6~8개, 보기 4개·정답 번호·보기 중복·문제 중복, 정답 낱말이 문제에 그대로 있는지, "정답 = 가장 긴 보기" 비율(같은 길이 포함) 10~33%, "정답 = 혼자 가장 짧은 보기" 33% 이하, 해설 해요체·조사 자리표시자, 어휘 문제의 와/과, 연습 문항이 1단계인지 본다. 이어서 정밀·빠른·적응형 출제를 수천 번 돌려 문항 수·단계·중복·연습 문항 재출제·안내 문항 수(`COUNT_KO`)·모든 문항이 한 번 이상 나오는지 확인한다.
- 언어 문항 작성 규칙(2026-10-16): 정답은 하나뿐이고 오답은 분명히 틀리거나 한쪽에만 맞는 것(공통점)으로 쓴다. 어휘는 표준국어대사전에 있는 낱말만 쓰고 동음이의어의 다른 뜻이 오답과 겹치지 않게 한다. 논리는 전제에서 "반드시" 따라 나오는 문장만 정답이고, 전제에 "거짓말"이 들어가면 질문이 "거짓말을 하는 사람은 누구일까요?"로 바뀐다. 해설은 해요체.

## 검사 구성

- 인지 능력: 5영역 18과제. 규칙 찾기(=유동 추론; 도형 행렬·도형 유추·도형 계열·수열·저울 추론), 언어(유추·어휘·논리·공통점 찾기), 공간(도형 회전), 기억(숫자 앞·뒤, 위치 기억, 숫자-문자 순서), 속도·주의(단순 반응·선택 반응·색-단어 간섭·기호 찾기). 빠른 검사(6과제: 도형 행렬·수열·어휘·도형 회전·숫자 거꾸로·기호 찾기, 적응형), 정밀 검사(18과제), 과제별 단독 검사(`task:<key>` 모드) 중 선택. 결과는 영역 → 과제 트리, 난이도별 정답률, 평균 응답 시간, 틀린 문항 복기.
  - 도형 유추(`figAnalogy`): A→B의 변환(채움·모양·틀·크기·개수·회전·반전·선·점)을 C에 적용. 1~5단계, 보기 6개 균형 배치. 저울 추론(`weights`): 가장 가벼운 도형을 1로 둔 정수 무게, 주어진 저울 1~2개로 관계를 알아내 마지막 저울을 맞춤, 보기 4개(무게가 모두 다름). 공통점 찾기(`similar`): 직접 쓴 35문항(단계마다 7개). 숫자-문자 순서(`lns`, 렌더러 `seqspan`): 2~8개, 숫자 오름차순 뒤 자음 ㄱㄴㄷ순, 응답은 전체 키패드에서. 기호 찾기(`symbol`, 렌더러 `symsearch`): 60초, 표적 2개·탐색 5개, 점수 = 정답 − 오답.
  - 도형 행렬 엔진: 한 칸 = 틀(네모·둥근·마름모·육각) + 안쪽 도형(8종, 개수·크기·위치·방향·좌우) + 선(가로·세로·대각 2) + 모서리 점(4곳). 규칙은 범주(행 고정·열 고정·라틴 분배), 진행(개수·크기·방향·위치 한 단계씩), 집합 논리(합집합·교집합·배타·빼기), 2×2에서는 "오른쪽 = 왼쪽의 변환"(진행·반전·고정 집합 더하기/빼기/뒤집기). 1~6단계, 4단계부터 2×2와 3×3 혼합, 보기 8개. 보기는 속성마다 4값×2 또는 2값×4로 정확히 균형을 맞춰 보기만 비교해서는 못 고른다(review.cjs로 검증).
  - 난이도: 모든 문항에 1~6단계가 있고 쉬운 것부터 나온다. 도형 행렬 4~6단계는 위 상위 규칙을 겹치고, 수열 4~5단계는 두 규칙 교대·소수·n²±n·세 항 합, 회전 4~5단계는 7칸 도형에 거울상 계열 오답, 유추·어휘·논리·공통점에도 4~5단계 문항이 있다. 문항 수(정밀 기준): 행렬 12, 도형 유추 10, 계열 6, 수열 8, 저울 8, 유추·어휘·논리·공통점 각 12, 회전 6.
  - 단계별 예상 정답률 `LEVEL_P`(1단계 92% → 6단계 12%)에서 각 단계의 난이도 b = ln((1−p)/p)를 정하고, 라쉬 모형 + 찍기 확률(1/보기 수)로 능력 θ의 사후 최빈값(사전분포 N(0, 1.5²), `irtTheta`)을 구해 z = θ로 쓴다. 실제 응시 자료로 보정하기 전까지는 설계상의 추정치다.
  - 적응형 모드(`adaptive`, 기본 추천)와 과제별 검사(`task:<key>`)는 과제 자리에 스텁(`type:'adaptive'`)을 두고 엔진이 `adaptNext()`로 문항을 그때그때 생성해 스텁 앞에 끼운다. 답이 오면 `adaptRecord()`가 맞히면 +1단계, 틀리면 −1단계로 조정한다(시작 3단계, 과제당 5~8문항, `ADAPT`). 스텁 상태는 세션에 저장되어 새로고침에도 이어진다.
  - 출제 방식: 규칙 찾기 5과제·도형 회전·기억 4과제·속도 4과제는 매번 새로 생성(난수). 언어 4과제는 직접 쓴 고정 문항 풀(유추·어휘·논리·공통점 각 35개, 1~5단계마다 7개)에서 고르고 보기 순서만 섞는다. 정밀 검사는 단계별 균등 표본 12문항(1·1·2·2·3·3·3·4·4·4·5·5단계, `LEVELS`), 적응형(빠른 검사 포함)은 그 단계에서 아직 안 본 문항을 무작위로 고른다(`drawPool`·`pickFromPool`). 다시 볼 때 같은 문항이 덜 나오도록 과제마다 최근에 낸 문항 24개를 기기에 남기고(`bl.verbalSeen`) 같은 단계에 안 본 문항이 있으면 그중에서 고른다. 그래서 두 번째 정밀 검사는 언어 문항이 거의 겹치지 않고, 세 번째부터는 단계마다 7개뿐이라 일부가 다시 나온다. 검수용 갤러리는 기록하지 않는다. 연습 문제로 쓰는 문항(`PRACTICE_ITEM`: 유추·공통점 0번, 논리 1번, 모두 1단계)은 연습에서 정답을 보여 주므로 점수 문항으로 다시 내지 않는다. 진행 중인 세션이 문항 번호를 저장하므로 새 문항은 배열 뒤에 붙인다.
  - 숫자-문자 순서(`seqspan`)의 응답은 반드시 전체 키패드(숫자 1~9, 자음 ㄱ~ㅅ)에서 고르게 한다. 방금 본 항목만 버튼으로 주면 기억 없이 정렬만 하면 되어 점수가 부풀었다(2026-10-15에 고침). "하나 지우기"로 마지막 탭만 되돌릴 수 있다.
  - 기억 과제 기준값(2026-10-15 조정): 숫자 앞으로 7.0±1.1, 거꾸로 5.2±1.2, 위치 6.0±1.1, 숫자-문자 5.3±1.1 (20~30대, 같은 길이 두 번 시도 규칙). 예: 7/5/6/6 → 기억 IQ 101, 8/6/7/7 → 116, 최대 9/8/9/8 → 140. 이전 기준(6.5/4.8/5.5/5.0)은 평균 성적이 110 안팎으로 나와 부풀어 보였다.
  - 반응 과제: 탭은 `pointerdown`으로 받고(클릭 지연 없음, 뒤따르는 click은 무시), 초록색이 그려진 프레임 시각을 기준점으로 잡는다. 응답의 절반 이상이 터치(`pointerType` touch/pen)면 기준값에 `TOUCH_MS`(30ms)를 더하고 결과에 "터치 기준"을 표시한다. 버튼에는 `touch-action: manipulation`을 두어 두 번 탭 확대를 막는다.
  - 점수는 IQ 척도(평균 100, 표준편차 15)로 환산한 "추정 IQ". 과제별 원점수를 `NORMS`(일반 성인 추정치, 공인 규준 아님)로 z 점수화하고, 영역은 r=0.6, 종합은 r=0.5 가정의 합성 공식으로 합친다. 표시 범위 55~145.
  - 따로 푼 과제는 `merge(results)` 가 과제별 최신 결과를 모아 종합 프로필(`#/profile/cognitive`)로 합친다.
  - 제한 시간: 문항 기본값(도형 행렬 60~80초, 도형 계열 40초, 수열 50초, 유추 40초, 어휘 35초, 논리 60초, 회전 40초)에 사용자가 고른 배수(표준 ×1 · 여유 ×1.5 · 무제한, localStorage `bl.timeFactor`)를 곱한다. 표준이 아니면 결과에 표시된다.
  - 처음 보는 과제(도형 행렬·도형 유추·계열·수열·저울·회전·유추·논리·공통점) 앞에는 점수에 안 들어가는 연습 문제가 하나 붙는다. 이미 해 본 과제는 건너뛴다.
  - 결과의 ±는 측정 오차(SEM). 과제 수 k에 대해 신뢰도 = k·0.3/(1+(k−1)·0.3), SEM = 15·√(1−신뢰도). 과제 하나만 푼 결과는 0.45. 0.3은 참값을 아는 가상 응시자 시뮬레이션에서 ± 안에 실제 값이 70% 안팎으로 들어오도록 맞춘 값이다(빠른 검사 ±8, 18과제 ±5).
  - 같은 검사를 다시 하면 결과 맨 위에 "지난 결과와 비교" 항목이 붙는다 (표시용, 저장 안 함).
- 정서 지능: 4영역 × 2세부 = 8세부. 문항 풀 48개(세부당 6개, 직접 쓴 상황 판단 문항). 기본 검사는 세부당 3개를 무작위로 뽑아 24문항, 정밀 검사는 48문항 전부. 영역이 번갈아 나오게 섞는다.
- 성격: 빅파이브 5요인 × 3세부 = 15세부. 문항 풀 90개(세부당 정방향 3·역방향 3, IPIP 바탕 번역·각색). 기본 검사는 세부당 정 2·역 2를 뽑아 60문항, 정밀 검사는 90문항 전부.
- 연애 애착: 불안·회피 2축 × 3세부 = 6세부. 문항 풀 48개(세부당 정 4·역 4, 직접 씀). 기본 검사는 세부당 정 2·역 2를 뽑아 24문항, 정밀 검사는 48문항 전부.
- 연애 스타일: 존 리의 사랑의 여섯 가지 스타일(열정형 에로스, 놀이형 루두스, 친구형 스토르게, 실용형 프래그마, 몰입형 마니아, 헌신형 아가페). 문항 풀 48개(스타일당 정 4·역 4, 직접 씀, "연애할 때/한다면" 꼴, 성별 가정 없음). 기본 검사는 스타일당 정 2·역 2를 뽑아 24문항, 정밀 검사는 48문항 전부. 결과는 60점을 넘는 스타일이 없거나 여섯 점수가 10점 안에 모이면 균형형, 둘째가 60점 이상이고 첫째와 8점 안이면 두 스타일을 함께(예: 열정형 · 친구형), 아니면 가장 높은 스타일 하나. 점수가 같으면 채점할 때 순서를 무작위로 정해 앞 순서(열정형) 쏠림을 막고, 가장 높은/낮은 스타일이 여럿이면 모두 적는다. 검증: `scratchpad/love-check.cjs <루트>`(정·역 균형, 중복, 다른 검사와 같은 문장, 성별 낱말, 같은 답만 고르면 모두 50점 균형형, 무작위 응답의 첫째 스타일 분포, 해요체·자리표시자·진단 표현).
- 진로 흥미 유형: 홀랜드의 여섯 흥미 유형(현실형·탐구형·예술형·사회형·진취형·관습형, 육각형 둘레 순서 R·I·A·S·E·C) × 세부 2개 = 12세부(기계·만들기, 자연·몸 쓰기 / 과학·실험, 분석·논리 / 그리기·디자인, 글·음악·공연 / 가르치기, 돌보기·상담 / 이끌기·설득, 사업·판매 / 정리·기록, 숫자·자료 관리). 문항 풀 72개(세부당 6개, 직접 쓴 "~기" 활동 문장). 문항 위에 "이 활동, 얼마나 해 보고 싶나요?"가 나오고 보기는 전혀 아니다·별로다·보통이다·해 보고 싶다·꼭 해 보고 싶다. 역문항 없이 모두 같은 방향이고 유형마다 문항 수가 같다. 기본 검사는 세부당 3개를 뽑아 36문항(유형마다 6), 정밀 검사는 72문항 전부이고, 세부 12개를 한 바퀴씩 내면서 같은 유형이 연달아 나오지 않게 섞는다. 결과는 점수 순 6유형 막대(세부 2개씩), 가장 높은 두 유형의 조합 제목(점수 순, 예: 탐구·예술형)과 조합별 별명 15개(배지), 첫째·둘째 유형 설명, 더 높은 세부에 맞춘 활동 예시, 조합별 직업 예시, 육각형 거리(이웃·한 칸·마주 봄), 가장 덜 끌리는 쪽, "흥미와 적성은 달라요" 안내. 가장 높은 유형과 가장 낮은 유형의 차이가 15점 미만이면 조합을 고르지 않고 평균에 따라 고르게 높음(60 이상)·보통·낮음(40 이하)으로 보여 준다(같은 답만 고르면 여기에 해당). 점수가 같으면 육각형 순서로 정하고 그렇게 정했다고 알려 주며, 둘째와 셋째가 5점 안이면 다른 조합도, 첫째가 둘째보다 25점 이상 높으면 첫째 하나를 중심으로 보라고 알려 준다. 검증: `scratchpad/interest.cjs <루트> [반복]`(유형·세부별 문항 수, 문장 중복과 비슷한 문장, "~기" 형식·길이, 기본·정밀 출제와 같은 유형 연속, 할 때마다 바뀌는지, 같은 답만 고를 때 고르게 낮음·보통·높음, 조합 30가지 제목·별명, 육각형 거리, 동점 안내, 무작위 응답 3000번, 결과 문장 해요체·조사·진단 표현, 요약 길이).
- 세 검사 모두 세부마다 정·역 문항 수가 같아야 한다. 정 2·역 1과 정 1·역 2를 섞으면 "매우 그렇다"만 고른 응답이 가짜 성격 유형(예: 에너자이저형 67점)을 만든다. 검증: `scratchpad/pools.cjs <루트>` (개수·균형, 중복, EQ 보기 길이 단서, 같은 답만 고를 때 균형형/안정형, 할 때마다 문항이 바뀌는지).

문항 렌더러 종류: `section`, `choice`, `likert`, `digitspan`, `gridspan`, `seqspan`, `reaction`, `choicert`, `stroop`, `symsearch`. 결과 객체의 `scales[].children` 이 세부 막대, `review[]` 가 복기 항목이다. `likert` 문항은 `labels`(보기 다섯 개 문구)와 `lead`(문장 위에 작게 나오는 질문 줄)를 따로 줄 수 있다.

## 법적 메모

- 도형 행렬과 수열 문항은 규칙 기반으로 매번 생성되는 원본 문항이다.
- 성격 검사 문항은 공개 도메인인 IPIP 항목을 바탕으로 번역·각색한 것이다.
- 도형 문항의 오답은 속성별로 값이 고르게 나오도록 만들어, 문제를 보지 않고 보기만 비교해서는 정답을 고를 수 없다. 정서 지능 보기는 길이를 비슷하게 맞췄다.
- 정서 지능, 애착, 연애 스타일 문항은 이 사이트를 위해 직접 썼다. 연애 스타일은 존 리의 이론(개념)만 빌렸고 Hendrick의 사랑 태도 척도(LAS) 문항은 옮기지 않았다.
- 진로 흥미 문항도 이 사이트를 위해 직접 썼고, 홀랜드의 여섯 유형 이론(개념)만 빌렸다. 공개 흥미 문항 모음(IIP)의 기초 흥미 척도(BIM, Liao·Armstrong·Rounds 2008)는 저자 저작권이 있고 전문가의 비상업적 사용만 무료로 허락되어 있어(2026-10-18 WSU 연구실 페이지 확인) 쓰지 않았다. RIASEC 마커는 O*NET 흥미 검사 문항에서 나온 것이라 역시 쓰지 않았고, 워크넷 직업흥미검사 문항도 옮기지 않았다. 결과의 직업은 예시로만 보여 주고, 흥미는 적성·능력과 다르다는 안내를 모든 결과에 붙인다.
- 모든 결과 화면에 "참고용 자기평가" 면책 문구가 붙는다. IQ 숫자나 진단 표현은 쓰지 않는다.
- 개인정보를 받지 않으며 결과는 localStorage에만 저장된다.

## 검색 노출과 공유

- `index.html`에 제목·설명·canonical·Open Graph·Twitter 카드·JSON-LD(WebSite)·manifest·favicon이 있고, 앱이 뜨기 전 정적 소개 블록(`.seo-static`)이 검색 엔진과 링크 미리보기에 읽힌다.
- `robots.txt`, `sitemap.xml`(홈 1건, 해시 라우트는 별도 URL이 아님), `og.png`(1200×630), `icon-192.png`/`icon-512.png`, `manifest.webmanifest`(홈 화면에 추가 가능).
- 이미지는 `make-images.ps1`(System.Drawing)로 만들었다. 문구를 바꾸려면 og-text.txt를 고쳐 다시 실행한다.
- 2026-10-18에 검사가 여섯 개가 되어 `og.png`를 같은 배치로 다시 그렸다("나를 측정하는 여섯 가지 실험", 부제는 여섯 검사 이름이고 넘치면 부제 글자 크기만 줄인다). OG 이미지만 다시 그리는 `scratchpad/og-only.ps1 -OutFile <png> -TextFile <txt>`(줄 순서: 제목, 부제, 태그, 문구, 아랫줄). 카카오톡은 미리보기 이미지를 캐시하므로 바뀐 이미지가 바로 안 보이면 카카오 개발자 사이트의 공유 디버거에서 캐시를 지운다.
- 구글 서치 콘솔 등록은 소유 확인이 필요하다(HTML 태그 방식: 콘솔이 주는 `<meta name="google-site-verification">` 태그를 `index.html` head에 넣고 커밋). 등록 후 sitemap.xml 제출.
- 카카오톡: 링크 미리보기는 OG 태그로 동작. "카카오톡 공유" 버튼은 `js/config.js`의 `kakaoKey`(developers.kakao.com 앱의 JavaScript 키)가 있을 때만 보인다. 키 없이도 "링크 복사"로 카톡에 붙여 넣을 수 있다.
  - 콘솔 설정 두 곳이 모두 필요하다 (앱 ID 1608815): ① 앱 > 플랫폼 키 > JavaScript 키 > JavaScript SDK 도메인에 `https://duscjf0098.github.io`(테스트용 `http://localhost:5173`), ② 앱 > 제품 링크 관리 > 웹 도메인에 `https://duscjf0098.github.io`. 카카오 문서상 ②에 없는 도메인의 링크는 쓸 수 없다("등록되어 있지 않은 도메인 또는 스킴은 사용할 수 없습니다"). 2026-10-15에 ②가 비어 있어 같은 날 `https://duscjf0098.github.io`를 등록했다(기본 웹 도메인). 공유 창(sharer.kakao.com 피커)의 미리보기에는 제목·설명·썸네일만 나오고 링크·버튼은 원래 안 보이므로, 링크가 살아 있는지는 실제로 보낸 메시지(예: 나와의 채팅)를 눌러 봐야 확인된다.
  - 코드: SDK는 결과 화면이 뜰 때 미리 불러 두고(`BL.card.preloadKakao`), 버튼 클릭 핸들러 안에서 `Kakao.Share.sendDefault`를 곧바로 부른다. 누른 뒤에 SDK를 내려받으면 사용자 동작 직후 상태가 끝나 휴대폰에서 첫 탭이 무시된다. 아직 준비 전이면 "1~2초 뒤에 한 번 더 눌러 주세요"를 띄운다.
