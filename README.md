# 두뇌실험실

인지 능력, 정서 지능, 성격, 연애 애착 유형, 연애 스타일, 진로 흥미 유형을 측정하는 자기평가 웹사이트. 서버 없이 정적 파일만으로 동작한다.

## 실행

```
node serve.cjs
```

브라우저에서 http://localhost:5173 을 연다. `index.html`을 더블클릭해도 동작한다.

## 구조

- `index.html` 진입점. 스크립트 로드 순서가 중요하다 (util → tests → card → app).
- `css/style.css` 밝고 부드러운 테마(2026-10-18, 크림 바탕·둥근 카드·알약 버튼). 색은 `:root` 토큰으로 관리한다. 사용자 결정으로 다크 모드 없이 항상 밝은 화면이다(`color-scheme: only light`, `<meta name="color-scheme" content="only light">`로 휴대폰·카카오톡 브라우저의 강제 어둡게도 막는다). 검사별 파스텔 색은 `.tint-<id>`(바탕·글자·강조·테두리)에 있고, `.tinted`를 붙인 화면은 그 색을 `--accent`로 써서 버튼·진행 막대·결과 막대가 검사 색을 따른다. 첫 화면 카드와 검사 소개의 질문형 제목은 `js/app.js`의 `LOOK`, 공유 이미지 색은 `js/card.js`의 `TINT`.
- 진행 화면(2026-10-18): 시간 제한이 없는 검사(정서 지능·성격·애착·진로 흥미·연애 스타일)는 "← 이전 문항"으로 돌아가 답을 바꿀 수 있고(전에 고른 답이 표시됨), 이미 답한 문항에서는 "다음 →"으로 넘어간다. 인지 검사는 제한 시간과 적응형 진행 때문에 되돌리기를 두지 않는다.
- `js/util.js` 난수(seeded RNG), HTML 이스케이프, 저장소 유틸.
- `js/stats.js` 익명 응시 통계: 인지 검사의 문항별 정답 여부·응답 시간과 과제별 원점수를 이름 없이 수집 서버에 보내고(끌 수 있음), 집계를 받아 결과 화면에 "실제 응시자 n명 기준 상위 %"를 붙인다. 서버는 `server/`(Cloudflare Workers + D1), 기준값 생성은 `tools/norms-from-stats.cjs`. 자세한 것은 "익명 통계 서버".
- `js/tests/*.js` 검사 정의. 각 파일은 `BL.tests.<id> = { build(), score(answers, items), ... }` 를 등록한다. 검사 정의에 `related: [{ id, why }]`를 두면 결과 화면 맨 아래에 그 검사로 가는 "이어서 해 보기" 카드가 붙는다(애착 ↔ 연애 스타일).
- `js/card.js` 결과 카드 PNG 생성(1080×1350), 저장, 공유.
- `js/app.js` 해시 라우팅, 문항 렌더러(choice / likert / digitspan / reaction / section), 결과·기록·안내 화면.

## 라우트

- `#/` 홈
- `#/test/<id>` 소개 · `#/run/<id>` 진행 · `#/result/<id>/<n>` 결과
- `#/preview/<id>` 무작위 응답으로 결과 화면만 미리보기 (디자인 작업용). 인지 검사는 `#/preview/cognitive/quick` 으로 빠른 검사 결과도 볼 수 있다.
- `#/history` 내 기록 · `#/about` 안내

검사 id: `cognitive`, `eq`, `personality`, `attachment`, `interest`, `love` (홈 카드 순서)

## 글 톤과 설명 블록

- 사용자에게 보이는 설명은 쉬운 말, 해요체로 쓴다(문항·정답 해설은 제외). 전문 용어는 꼭 필요할 때 한 번만 쓰고 바로 풀어 준다.
- 영역·갈래·축마다 `what`(무엇을 재나)과 `where`(일상에서 어디에 쓰이고 어떤 영향을 주나)를 둔다. 각 검사 객체의 `explain` 배열이 **결과 화면**의 "무엇을 잰 걸까요, 어디에 쓰일까요" 블록이 된다(소개 페이지에는 두지 않는다; 결과에 나온 영역만 표시). 인지 과제 20개는 `TASKS[k].where`가 과제 시작 카드에 "일상에서" 줄로 나온다.

## 문항 갤러리 (검수용)

- `#/gallery/<과제 키>/<단계 또는 all>[/<단계당 개수>]` — 예: `#/gallery/matrix/all`, `#/gallery/weights/5/3`. 생성 문항을 연습 모드(타이머 없음)로 쭉 그려 주고 정답 보기를 초록 테두리로 표시한다. 저장되지 않는다. 과제 키: matrix, figAnalogy, series, sequence, weights, rotation, fold, blocks (analogy·vocab·logic·similar도 됨).
- 도형 그리기 규칙(2026-10-15 점검): 마름모 틀은 안쪽이 좁아 도형 3~4개와 겹치므로 틀은 none·square·circle·hexagon만 쓴다. 모서리 점은 (13,13)·(87,87) 등 셀 구석에 두어 둥근·육각 틀과 큰 도형 4개에 겹치지 않는다. 저울 보기 접시는 7개까지 올라가므로 접시를 넓게(10~110) 그린다.
- 그림 읽기 쉬움(2026-10-18 점검): 크기 단계는 반지름 7.2·10.2·14.2(약 1.4배씩)로, 예전 8·11·14는 "중간"과 "크게"를 가리기 어려웠다. 같은 단계면 모양이 달라도 비슷한 크기로 보이게 모양마다 크기를 보정한다(`SHAPE_FIT`). 도형 여럿은 클수록 간격을 벌리고 육각 틀은 반지름 48로 그려, 크게·4개·어느 틀에서도 도형·틀·모서리 점이 1단위 넘게 떨어진다. 보기 크기에서 눈으로 가리기 어려운 칸(작은 별·십자·화살표·ㄱ자의 반 채움·점·빗금, 작은 삼각형의 점·빗금, 한 문항에 원과 육각형이 함께 나오면서 어느 하나가 작음)이 생기면 `legible()`이 걸러 문항을 다시 만든다. ㄱ자·화살표의 점 채움은 도형 안쪽(꺾인 모서리·몸통)에 찍는다. 보기 단추는 안쪽 칸 테두리를 빼 그림이 커졌고(폰 약 73px), 도형 계열 칸은 빈 가장자리를 잘라 크게 보인다(`cell.zoom`).
- 전개도·블록 그리기(2026-10-18): 전개도 칸은 100단위이고 무늬 8종(화살표·삼각형·점·막대·T자·반원·ㄴ자·깃발) 중 점(칸 가운데 동그라미)은 돌려도, 막대(칸 가운데 가로 띠)는 반 바퀴 돌려도 같고, 나머지는 돌리면 달라 보이며 ㄴ자·깃발은 뒤집어도 달라 보인다. 눈으로 방향이 안 보이는 무늬는 그림도 대칭으로 그려서 보이지 않는 "방향"으로 정답이 갈리지 않는다(2026-10-18, 전에는 점이 칸 위쪽에, 막대가 위 가장자리에 있어 자리만 다른 오답이 2단계 문항의 3분의 1에 나왔다). 정육면체 보기는 100×100 좌표에 모서리 42인 등각 투영으로 위·왼쪽 앞·오른쪽 앞 세 면을 그리고(보기 높이를 줄이려고 viewBox는 정육면체 둘레에 맞게 `12.5 7 75 86`으로 자른다), 옆면은 잉크색을 옅게 겹쳐 어둡게 한다. 무늬는 `<g data-p="무늬" transform="matrix(…)">` 하나로 그려 검사 스크립트가 꼭짓점 화면 좌표를 바로 읽는다. 블록은 보이는 면만 먼 것(x−y+z가 작은 것)부터 그리고, 면 색은 `--blk-t/l/r` 토큰으로 칠한다(사이트가 밝은 테마 하나라 값도 한 벌).

## 문구 검증

- `scratchpad/text.cjs <루트>`: 생성 문항 수천 개와 모든 결과 문장(검사·모드별 무작위 응답)을 만들어, 조사 자리표시자("을(를)", "이(가)", "(으)로", "와(과)")·딱딱한 합니다체("~니다", 문항 속 "아니다"는 제외)·깨진 값(undefined/NaN)이 없는지 확인한다. 조사는 항상 `U.josa(단어, 받침 있을 때, 없을 때)`로 붙인다. 불러오는 파일 목록이 고정이라 새 검사 파일을 더하면 목록에 넣어 돌린다.

## 정답 검증

- `scratchpad/audit.cjs <루트> [반복]`: 생성 문항(행렬·유추·계열·수열·저울·회전)을 단계별로 수천 개 만들어, 보이는 칸·저울·도형만으로 다시 계산한 정답이 보기 중 정확히 하나인지 확인한다. 저울은 1~9 범위의 모든 무게 조합 중 주어진 저울과 맞는 조합 전부에서 정답만 평형이어야 하고, 2×2 집합 논리는 예시 행에 맞는 모든 (연산, K′) 가설이 같은 답을 내야 한다(`kUnique`).
- 2026-10-15에 잡은 오류: (1) 2×2 집합 논리에서 숨은 K가 예시 왼쪽 칸과 겹치면 "보이는 변화"로 추론한 답이 정답과 달라졌다 → `logicK`가 가설 전수 검사를 통과하는 조합만 쓴다. (2) 저울 추론 4~5단계에서 한쪽에 2개를 올릴 때 반대쪽에 6개 이상이 필요하면 접시 한도(5개) 때문에 엉뚱한 저울이 그려졌다 → 2개 올리기는 2·무게 ≤ 5일 때만. (3) 수열 `primesSkip`의 2, 5, 11, 17, 23은 "+6"으로도 읽혀 모호 → `altNext`에 뒤쪽 세 차이가 같은 경우를 추가.
- `scratchpad/spatial.cjs <루트> [반복]`(2026-10-18): 전개도 접기·블록 세기 정답 검사. 생성 코드를 쓰지 않고 그려진 SVG만 읽는다. 전개도는 종이 칸을 맞닿은 변을 축으로 실제로 90°씩 접어(로드리게스 회전) 정육면체를 만들고, 24가지로 돌린 모습을 (1,−1,1) 쪽 정사영으로 그려 무늬 꼭짓점 좌표를 보기와 맞춰 본다 → 나올 수 있는 보기가 정확히 하나이고 그게 정답 번호인지, 보기끼리 같은 그림이 없는지, 해설의 마주 보는 면과 정답 면 위치가 맞는지. 정육면체 전개도가 11가지라는 것도 헥소미노 35개를 직접 접어 보아 따로 구한다. 블록은 다각형을 삼각 격자에 그린 순서대로 칠해 보이는 면을 구하고, 면 방향에 따라 격자 한 칸이 3차원에서 어느 쪽인지로 보이는 표면을 이어 붙여 기둥 높이를 복원한 뒤, 다시 그려 같은 그림이 나오는지 본다 → 다시 센 수가 보기 중 정확히 하나이고 정답 번호인지, 보기가 작은 순·정답 ±3 안인지, 해설의 층별·보이는·가려진 개수가 맞는지. 정밀·적응형·과제별 구성과 채점도 돌린다. 생성기를 일부러 틀리게 고친 여섯 경우(접는 방향, 무늬 회전 방향, 거울상을 정답으로, 블록 면 조건, 정답 번호, 구석이 아닌 쌓기)를 모두 잡는 것을 확인했다.
- 도형 회전을 보기만 보고 풀기(2026-10-18): 오답 셋이 모두 같은 거울상을 돌린 것이라, 보기끼리 돌려 맞춰 보고 혼자 다른 보기를 고르면 문제 도형을 보지 않아도 늘 정답이다. 이 방법도 머릿속 회전이 있어야 풀리므로 설계상 받아들인 대가로 둔다. 그래서 `scratchpad/review.cjs`의 회전 항목은 돌리지 않고도 보이는 특징으로 고르는 요령(바깥 크기·줄마다 칸 수가 혼자 다른 보기 고르기, 보기들의 바깥 크기 방향이 문제와 같은지·뒤바뀌었는지가 몇 개씩 나뉘는지 보고 고르기)이 우연(25%) 수준인지 보고, 보기끼리 돌려 맞춰 보는 방법의 적중률은 참고로만 찍는다. 바깥 크기 방향은 생성기가 늘 2:2로 맞춘다.
- `scratchpad/verbal.cjs <루트> [반복]`: 언어 4과제 문항 풀 검사. 풀마다 35개 이상·단계마다 6~8개(2026-10-18 단계 재조정 뒤로는 단계별 개수가 고르지 않아 이 항목만 실패로 나온다. 공통점 5단계를 채운 뒤 다시 맞춘다), 보기 4개·정답 번호·보기 중복·문제 중복, 정답 낱말이 문제에 그대로 있는지, "정답 = 가장 긴 보기" 비율(같은 길이 포함) 10~33%, "정답 = 혼자 가장 짧은 보기" 33% 이하, 해설 해요체·조사 자리표시자, 어휘 문제의 와/과, 연습 문항이 1단계인지 본다. 이어서 정밀·적응형 출제를 수천 번 돌려(빠른 검사는 적응형이 되고 유추가 빠져서 그 확인은 빼고 돌린다) 문항 수·단계·중복·연습 문항 재출제·안내 문항 수(`COUNT_KO`)·모든 문항이 한 번 이상 나오는지 확인한다.
- 언어 문항 작성 규칙(2026-10-16): 정답은 하나뿐이고 오답은 분명히 틀리거나 한쪽에만 맞는 것(공통점)으로 쓴다. 어휘는 표준국어대사전에 있는 낱말만 쓰고 동음이의어의 다른 뜻이 오답과 겹치지 않게 한다. 논리는 전제에서 "반드시" 따라 나오는 문장만 정답이고, 전제에 "거짓말"이 들어가면 질문이 "거짓말을 하는 사람은 누구일까요?"로 바뀐다. 해설은 해요체.

## 검사 구성

- 인지 능력: 5영역 20과제. 규칙 찾기(=유동 추론; 도형 행렬·도형 유추·도형 계열·수열·저울 추론), 언어(유추·어휘·논리·공통점 찾기), 공간(도형 회전·전개도 접기·블록 세기), 기억(숫자 앞·뒤, 위치 기억, 숫자-문자 순서), 속도·주의(단순 반응·선택 반응·색-단어 간섭·기호 찾기). 빠른 검사(7과제: 도형 행렬·수열·어휘·도형 회전·전개도 접기·숫자 거꾸로·기호 찾기, 적응형. 전개도 접기는 2026-10-18에 공간을 두 과제로 재려고 더함), 정밀 검사(20과제), 과제별 단독 검사(`task:<key>` 모드) 중 선택. 결과는 영역 → 과제 트리, 난이도별 정답률, 평균 응답 시간, 틀린 문항 복기.
  - 도형 유추(`figAnalogy`): A→B의 변환(채움·모양·틀·크기·개수·회전·반전·선·점)을 C에 적용. 1~5단계, 보기 6개 균형 배치. 저울 추론(`weights`): 가장 가벼운 도형을 1로 둔 정수 무게, 주어진 저울 1~2개로 관계를 알아내 마지막 저울을 맞춤, 보기 4개(무게가 모두 다름). 공통점 찾기(`similar`): 직접 쓴 47문항(단계별 18·15·6·6·2개). 숫자-문자 순서(`lns`, 렌더러 `seqspan`): 2~8개, 숫자 오름차순 뒤 자음 ㄱㄴㄷ순, 응답은 전체 키패드에서. 기호 찾기(`symbol`, 렌더러 `symsearch`): 60초, 표적 2개·탐색 5개(모양 3가지 × 방향 4가지라 방향까지 같아야 같은 기호), 점수 = 정답 − 오답. 처음이면 시간 제한 없는 연습 4문제(틀리면 이유를 보여 줌). 진행 중에는 맞힌 수를 숨기고, 새 문항이 뜬 뒤 250ms 안의 입력과 키 자동 반복은 답으로 치지 않으며(따로 셈), 화면을 벗어나면 시간을 멈추고 판을 가린다. 정확도 70% 미만은 "측정 안 됨".
  - 전개도 접기(`fold`, 2026-10-18): 정육면체 전개도 11가지 중 하나를 돌리기·뒤집기로 놓되 늘 가로로 눕혀(8가지 놓임 중 가로로 긴 4가지) 그리고 면마다 다른 무늬를 넣는다. 무늬는 상자 바깥면에 있다. 보기 4개는 위·왼쪽 앞·오른쪽 앞 세 면이 보이는 정육면체이고, 오답은 마주 보는 두 면이 함께 보이는 것, 무늬 하나가 돌아간 것, 두 면 자리가 바뀐 것, 전체 거울상이다. 오답은 정답이 아니라 나올 수 있는 모습 24가지 중 무작위로 고른 것에서 한 군데를 바꿔 만든다(2026-10-18. 정답에서 바꾸면 정답이 모든 오답과 면을 가장 많이 공유해서, 보기끼리 겹치는 면이 가장 많은 것을 고르면 1단계 94%가 맞았다 → 지금 24~27%). 1·2단계는 정답을 "보이는 면이 전개도에서도 붙어 있는" 모습에서 고르므로 오답의 출발점도 같은 조건에서 고른다(정답에만 걸면 보이는 세 면이 전개도에서 가장 많이 붙은 보기 고르기가 1단계 74%·2단계 38%였다 → 66%·34%. 1단계에 남는 몫은 마주 보는 면 오답에서 오는 설계). 화면: 폰 한 화면(약 390×700)에 보기 둘째 줄까지 들어가게 전개도 칸은 `min(62px, 7vh)`, 정육면체 보기는 폭 `min(120px, 14vh)`이고(svh를 아는 브라우저에서는 아래 도구 막대가 펴진 높이 기준인 svh로 잰다), 질문은 한 줄("전개도를 접으면 나올 수 있는 모양은?")이다. 한 화면에 드는지는 CSS 값으로 어림한 것(390×700에서 넷째 보기 아래끝 최대 656px, 360×640에서 624px)이고 실제 폰에서는 아직 재지 않았다. 연습 문항은 질문 앞에 "연습 · "가 붙어 360px 폭에서 두 줄이 된다. 검사 화면(`body.running`)에서는 상단 바를 고정하지 않는다. 단계: 1단계 1-4-1 꼴·전개도에서도 붙어 있는 세 면·오답 셋 다 마주 보는 면, 2단계 + 무늬 하나 거꾸로, 3단계 2-3-1 꼴까지·마주 보는 면/무늬 돌림/자리 바뀜, 4단계 11가지 모두·무늬 돌림/자리 바뀜/거울상(마주 보는 면 오답 없음), 5단계 1-4-1이 아닌 5가지·무늬 90° 돌림 둘과 거울상. 3단계부터 전개도 위 무늬도 돌려 놓고, 4단계부터 ㄴ자·깃발 무늬도 쓴다. 보기 비교는 실제로 그린 무늬 꼭짓점의 화면 좌표로 해서 무늬 자체의 대칭 때문에 같은 그림이 되는 경우까지 걸러 낸다.
  - 블록 세기(`blocks`, 2026-10-18): 뒤쪽 구석이 가장 높고 앞으로 올수록 낮거나 같은 쌓기만 써서 모든 기둥의 윗면이 보이고 그림 하나로 개수가 정해진다. 그림 아래에 "블록은 모두 바닥이나 다른 블록 위에 놓여 있고, 옆 블록과 면이 맞닿아 한 덩어리로 붙어 있어요. 위에 블록이 있으면 그 아래에도 블록이 있고, 그 밖에 숨은 블록은 없어요."를 늘 적는다. 등각 그림에서는 맨 아래가 가려진 뒤쪽 기둥을 대각선 뒤로 한 칸 옮기고 한 층 낮춰도 그림이 같아서, "한 덩어리로 붙어 있다"는 문장으로 따로 떨어져 선 기둥으로 읽는 것을 막는다(2026-10-18). 단계별 바닥·높이·개수: 1단계 2×2~2×3·2층·4~8개, 2단계 2×3~3×3·3층·7~13개(가려진 블록 1개 이상), 3단계 3×3·3층·11~18개, 4단계 3×4~4×4·4층·16~26개, 5단계 4×4·4층·24~34개. 보기는 정답이 들어간 연속한 네 수이고 정답 자리(정답보다 작은 보기 0~3개)는 고르게 정한다(2026-10-18. 전에는 정답 ±1~3을 따로 뽑아 보기 간격 모양만 보고 고르면 58%가 맞았다 → 지금 25%). 가려진 블록 수가 정답보다 작은 보기 수 이하이면 보이는 블록만 센 수가 저절로 오답에 들어간다. 블록 옆면 색은 윗면과 대비 1.5:1 이상(WCAG 상대 휘도 기준 `--blk-l #d2cafb` 1.55:1, `--blk-r #a89cef` 2.4:1, 두 옆면끼리 1.57:1). 해설은 층별 개수와 보이는·가려진 블록 수.
  - 도형 행렬 엔진: 한 칸 = 틀(네모·둥근·마름모·육각) + 안쪽 도형(8종, 개수·크기·위치·방향·좌우) + 선(가로·세로·대각 2) + 모서리 점(4곳). 규칙은 범주(행 고정·열 고정·라틴 분배), 진행(개수·크기·방향·위치 한 단계씩), 집합 논리(합집합·교집합·배타·빼기), 2×2에서는 "오른쪽 = 왼쪽의 변환"(진행·반전·고정 집합 더하기/빼기/뒤집기). 1~6단계, 4단계부터 2×2와 3×3 혼합, 보기 8개. 보기는 속성마다 4값×2 또는 2값×4로 정확히 균형을 맞춰 보기만 비교해서는 못 고른다(review.cjs로 검증).
  - 난이도: 모든 문항에 1~6단계가 있고 쉬운 것부터 나온다. 도형 행렬 4~6단계는 위 상위 규칙을 겹치고, 수열 4~5단계는 두 규칙 교대·소수·n²±n·세 항 합, 회전은 단계마다 5·6·7·8·9칸 도형(5×5 격자 안)이고 오답 셋은 모두 거울상을 서로 다른 방향으로 돌린 것이라 칸 수·바깥 크기로는 거를 수 없다(2026-10-18. 전에는 오답 둘이 칸 하나를 옮긴 모양이라 칸만 세어도 둘이 지워졌고, 1·2단계와 4·5단계가 같은 조건이었다), 전개도 4~5단계는 어려운 전개도 꼴과 무늬 방향·거울상 오답, 블록 4~5단계는 4층까지 16~34개, 유추·어휘·논리·공통점에도 4~5단계 문항이 있다. 문항 수(정밀 기준): 행렬 12, 도형 유추 10, 계열 6, 수열 8, 저울 8, 유추·어휘·논리·공통점 각 12, 회전·전개도·블록 각 6(1·2·3·4·5·5단계). 2026-10-18 AI 평가자 보정: 과제마다 AI 평가자를 따로 3번 돌려 문항(생성 과제는 단계별 표본)마다 보통 성인의 정답률을 추정하고, 그 평균에서 찍기 몫을 빼서 `LEVEL_P`를 과제별 표(12과제, `default`는 그대로)로 바꿨다. 그림 과제는 평가자가 그림 대신 규칙 설명만 읽었으므로 설계값과 반반 섞었다. 언어 4풀은 같은 추정값으로 기존 140문항 중 76개(유추 22·어휘 8·논리 18·공통점 28)의 단계를 다시 매기고(경계: 관측 정답률 0.895·0.783·0.64·0.501), 비어 버린 상위 단계를 새로 쓴 29문항(유추 10·어휘 2·논리 5·공통점 12)으로 채웠다. 새 문항은 작성 1명·눈가림 풀이 2명·평가 3명(기준 문항으로 평가자마다의 치우침을 뺌)을 거쳐 두 풀이가 모두 맞히고 추정 정답률이 목표 단계에 든 것만 썼다. 이어서 리뷰에서 정답이 둘로 읽히거나 해설이 틀린 8문항을 고치고, 내용이 바뀐 문항은 같은 방식으로 단계를 다시 매겼다. 공통점 5단계는 어렵게 쓰기가 힘들어 2개뿐이라 그 자리에는 4단계 문항이 대신 나온다. 기준값 버전은 `ai-est-2026-10-18b`(같은 날 공간 수정 뒤 회전·전개도·블록 `LEVEL_P`를 새 생성기 표본으로 다시 어림함: AI 평가자 1명이 단계별 표본을 그림까지 보고 어림한 정답률에서 찍기 몫을 빼 설계값과 반반, 블록은 보기 구성 변화를 셈 오차 모형으로 따로 어림해 평균. 회전 .78/.68/.55/.42/.32, 전개도 .82/.65/.45/.32/.20, 블록 .89/.75/.56/.35/.19. 실제 자료로 다시 매겨야 한다).
  - 단계별 예상 정답률 `LEVEL_P`(과제별 표, 찍기 몫을 뺀 능력 부분. 기본표는 1단계 92% → 6단계 12%)에서 각 단계의 난이도 b = ln((1−p)/p)를 정하고, 라쉬 모형 + 찍기 확률(1/보기 수)로 능력 θ의 사후 최빈값(사전분포 N(0, 1.5²), `irtTheta`)을 구해 z = θ로 쓴다. 실제 응시 자료로 보정하기 전까지는 설계값과 AI 추정치다. 보정 경로는 "익명 통계 서버"(수집 → `/stats` 집계 → `tools/norms-from-stats.cjs --write`). 기준값 버전은 `NORMS_VERSION`(결과와 전송 자료에 붙음).
  - 적응형 모드(`adaptive`, 기본 추천)와 과제별 검사(`task:<key>`)는 과제 자리에 스텁(`type:'adaptive'`)을 두고 엔진이 `adaptNext()`로 문항을 그때그때 생성해 스텁 앞에 끼운다. 답이 오면 `adaptRecord()`가 맞히면 +1단계, 틀리면 −1단계로 조정한다(시작 3단계, 과제당 5~8문항, `ADAPT`. 공간 세 과제는 보기가 4개라 정보가 적어 2026-10-18에 5 → 7문항). 스텁 상태는 세션에 저장되어 새로고침에도 이어진다.
  - 출제 방식: 규칙 찾기 5과제·공간 3과제·기억 4과제·속도 4과제는 매번 새로 생성(난수). 언어 4과제는 직접 쓴 고정 문항 풀(유추 45·어휘 37·논리 40·공통점 47개, 1~5단계. 단계별 개수는 유추 13·11·8·5·8, 어휘 9·7·7·7·7, 논리 8·8·11·6·7, 공통점 18·15·6·6·2)에서 고르고 보기 순서만 섞는다. 정밀 검사는 단계별 균등 표본 12문항(1·1·2·2·3·3·3·4·4·4·5·5단계, `LEVELS`), 적응형(빠른 검사 포함)은 그 단계에서 아직 안 본 문항을 무작위로 고른다(`drawPool`·`pickFromPool`, 그 단계에 남은 문항이 없으면 가장 가까운 단계에서). 다시 볼 때 같은 문항이 덜 나오도록 과제마다 최근에 낸 문항 24개를 기기에 남기고(`bl.verbalSeen`) 같은 단계에 안 본 문항이 있으면 그중에서 고른다. 그래서 두 번째 정밀 검사는 언어 문항이 거의 겹치지 않고, 세 번째부터는 일부가 다시 나온다(문항이 적은 단계, 특히 공통점 3~5단계는 더 일찍). 검수용 갤러리는 기록하지 않는다. 연습 문제로 쓰는 문항(`PRACTICE_ITEM`: 유추·공통점 0번, 논리 1번, 모두 1단계)은 연습에서 정답을 보여 주므로 점수 문항으로 다시 내지 않는다. 진행 중인 세션이 문항 번호를 저장하므로 새 문항은 배열 뒤에 붙인다.

  - 반응 과제(2026-10-18 손봄): 탭은 `pointerdown`으로 받고(클릭 지연 없음, 뒤따르는 click은 무시), 세 반응 과제 모두 자극이 그려진 프레임 시각(이중 `requestAnimationFrame`)을 기준점으로, 입력 이벤트의 `timeStamp`(지금 시각과 1초 넘게 다르면 `performance.now()`)를 응답 시각으로 잡는다. 단순 반응은 10번(처음이면 연습 3번, 해 본 사람도 몸풀기 1번)이고, 대기 시간이 1초 + 지수분포(평균 1.2초, 5초 이하)라 박자를 짐작할 수 없다. 신호는 어두운 화면에서 밝은 화면 + 흰 동그라미 + "지금!"으로 바뀌어 색에만 기대지 않는다. 대기 중 탭과 너무 빠른 탭(터치 150ms, 마우스 130ms 미만)은 '일찍 누름'으로 세어 3번 이상이면 z를 0까지만, 10번 이상이면 "측정 안 됨". 선택 반응(16번)·색-단어 간섭(32번, 색이 다른 문제 16번)은 처음이면 연습 4번을 하고, 실수 한 번은 봐주고 그다음부터 실수마다 채점 시간에 60ms(선택)·40ms(색-단어, 색이 다른 문제 16개 기준)를 더한다. 정확도가 찍기와 가려지지 않으면(선택 12/16 이하, 색-단어는 색이 다른 문제나 같은 문제를 절반 이하로 맞힘) "측정 안 됨"이고, 두 과제 모두 실수가 하나라도 있는데 맞힌 반응 중앙값이 기준값으로 z +2.75(IQ 141, 선택 반응 터치 280ms·그 밖 250ms, 색-단어 486·456ms)보다 빠르면 짐작으로 보고 "측정 안 됨"으로 둔다. 너무 빠른 응답(선택 터치 180·그 밖 150ms, 색-단어 200·170ms)과 너무 늦은 응답(2초·3초)은 기록하지 않고 다시 잰다. 시행마다 입력 방식(터치·마우스·키보드)을 적고 마우스가 절반을 넘으면 결과에 알린다. 측정 안 된 과제는 영역·종합 점수와 익명 통계에서 빠지고 종합 프로필에서 예전 결과를 덮지 않는다. 새로고침으로 과제를 처음부터 다시 시작한 횟수는 결과에 남는다. 응답의 절반 이상이 터치(`pointerType` touch/pen)면 기준값에 `TOUCH_MS`(30ms)를 더하고 결과에 "터치 기준"을 표시한다. 버튼에는 `touch-action: manipulation`을 두어 두 번 탭 확대를 막는다.

  - 결과의 ±(SEM) = √(측정 오차² + 덜 푼 몫²). 측정 오차는 과제 수 n에 대해 신뢰도 = n·0.3/(1+(n−1)·0.3), 15·√(1−신뢰도)(스피어먼-브라운). 덜 푼 몫은 전체 K과제 중 n개, 다섯 영역 중 m개만 풀어 종합 IQ를 덜 대표하는 만큼으로 6²·(1−n/K) + 4²·(1−m/5)를 더한다(빠른 검사 ±9, 20과제 ±5). 과제 하나만 푼 결과는 그 과제 점수의 오차라 0.45로 측정 오차만 쓴다(±11). 규준화 전 → 후(2026-10-18, 가상 응시자 6000명, 참값 표준편차 14.5): 빠른 7과제 RMSE 7.8 → 8.4, ± 안에 실제 값 66%(±7) → 74%(±9), 표준편차 12.0 → 15.9, 끝 치우침(참값 77.5 미만 / 122.5 이상인 사람의 평균 오차) +9.7/−7.2 → +2.5/−1.3. 적응형 20과제 5.4 → 4.9, 70% → 74%(±5), 11.3 → 15.2, +8.5/−7.1 → +0.8/+0.1. 정밀 20과제 4.9 → 4.7, 74% → 75%(±5), 11.4 → 15.9, +7.7/−6.8 → −1.0/+0.6. 따로 푼 과제 2~19개를 합친 종합 프로필은 69~77%, 과제 하나는 75%. 측정 오차만 쓰면 규준화 뒤 빠른 검사가 ±7, 63%로 좁아서 덜 푼 몫을 더했다. 과제 하나만 푼 점수는 규준화하지 않아(문항이 5~12개라 사후 최빈값이 평균 쪽으로 당겨짐) 끝에서 6~8점 평균 쪽으로 나오고, 결과 화면 "점수 읽는 법"에 그렇게 적는다. 과제를 2~6개만 합친 프로필도 끝 치우침이 7~10점 남지만 ±가 10~12로 넓다. 요약의 "가장 약한 영역" 문구는 가장 높은 영역과 가장 낮은 영역의 차이가 두 영역 SEM을 합친 √(SEM_a² + SEM_b²) 이상일 때만 쓴다(2026-10-18, 영역 SEM = 과제 하나 신뢰도 `TASK_REL`(가상 응시자 재검사 상관에서 구함)을 푼 과제 수만큼 스피어먼-브라운으로 합친 값). 차이가 8점 이상이어도 그보다 작으면 "오차 범위 안"이라고 쓴다. 전에는 차이 8점 이상이면 늘 약점 문구를 써서 모든 과제 실력이 같은 가상 응시자도 적응형 94%·빠른 98%가 받았다(지금 83%·78%). 검증: `sim-quick2.cjs <루트> [N] 0,10,11`(sim-quick.cjs에 전개도 접기·블록 세기를 더한 판, g 부하 0.62·0.58 가정), 값 맞추기: `sim-save.cjs <루트> 6000 out.json` → `ana6.cjs out.json '<OBS JSON>'`(모두 공유 노트 폴더).

- 도형 행렬과 수열 문항은 규칙 기반으로 매번 생성되는 원본 문항이다. 전개도 접기·블록 세기도 규칙으로 매번 새로 그린다(정육면체 전개도 11가지는 도형의 성질이고, 무늬와 그림은 직접 만들었다).
- 성격 검사 문항은 공개 도메인인 IPIP 항목을 바탕으로 번역·각색한 것이다.
- 도형 문항의 오답은 속성별로 값이 고르게 나오도록 만들어, 문제를 보지 않고 보기만 비교해서는 정답을 고를 수 없다. 정서 지능 보기는 길이를 비슷하게 맞췄다.
- 정서 지능, 애착, 연애 스타일 문항은 이 사이트를 위해 직접 썼다. 연애 스타일은 존 리의 이론(개념)만 빌렸고 Hendrick의 사랑 태도 척도(LAS) 문항은 옮기지 않았다.
- 진로 흥미 문항도 이 사이트를 위해 직접 썼고, 홀랜드의 여섯 유형 이론(개념)만 빌렸다. 공개 흥미 문항 모음(IIP)의 기초 흥미 척도(BIM, Liao·Armstrong·Rounds 2008)는 저자 저작권이 있고 전문가의 비상업적 사용만 무료로 허락되어 있어(2026-10-18 WSU 연구실 페이지 확인) 쓰지 않았다. RIASEC 마커는 O*NET 흥미 검사 문항에서 나온 것이라 역시 쓰지 않았고, 워크넷 직업흥미검사 문항도 옮기지 않았다. 결과의 직업은 예시로만 보여 주고, 흥미는 적성·능력과 다르다는 안내를 모든 결과에 붙인다.
- 모든 결과 화면에 "참고용 자기평가" 면책 문구가 붙는다. IQ 숫자나 진단 표현은 쓰지 않는다.
- 개인정보를 받지 않으며 결과는 localStorage에만 저장된다. 인지 검사의 문항별 정답 여부(문항 내용이 아니라 번호)·응답 시간과 과제별 원점수만 익명 통계로 보낼 수 있고(기본 참여, 첫 결과 화면과 안내 페이지에서 끌 수 있음), 서버에도 이름·연락처·IP·기기 식별자·정확한 시각을 저장하지 않는다("익명 통계 서버"). 문항 자체는 바꾸지 않았다.

## 익명 통계 서버 (server/)

인지 검사의 임시 기준값(`NORMS`·`LEVEL_P`)을 실제 응시 자료로 보정하기 위해, 2026-10-18부터 결과의 과제별 원점수를 익명으로 모은다. 정적 사이트는 그대로 GitHub Pages에 있고, 수집 서버만 Cloudflare Workers + D1에 둔다(무료 티어: 하루 요청 10만 건, D1 읽기 500만·쓰기 10만 행, 저장 5GB. 이 사이트 규모에는 충분하다).

- 보내는 것(`js/stats.js`, 인지 검사만): 검사 id, 모드, 시간 설정, 입력 방식(터치/마우스, `pointer: coarse`), 기준값 버전(`NORMS_VERSION`), 종합 z, 과제별 { z, 정답 수·문항 수, 단계별 정답 수(`levels`), 적응형 여부, 문항마다 `[풀 번호, 단계, 정답 1·오답 0·시간 초과 -1, 응답 시간(0.1초)]`(`items`), 기억 폭, 반응 시간 중앙값, 정확도, 터치 여부 }. 2026-10-18부터 반응·기호 찾기 과제에는 일찍 누름·너무 빠름·너무 늦음·다시 시작·화면 벗어남 횟수, 입력 방식(터치·마우스·키보드), 감점 전 중앙값·간섭값도 붙는다(서버가 아직 저장하지 않는 필드는 서버가 버린다). 정확도가 찍기 수준이라 "측정 안 됨"인 과제는 보내지 않는다. 원점수는 `cognitive.js`의 `taskStats`가 `tasks[k].obs`에 넣는다(z 계산 전 값). 풀 번호는 언어 4과제의 고정 문항 풀 번호(`choiceItems`가 붙이는 `pid`, 풀은 뒤에만 붙이므로 번호가 바뀌지 않는다)이고, 그때그때 만드는 도형·숫자 문항은 -1과 단계만 보낸다. 문항 내용, 이름·이메일·IP·User-Agent·기기 식별자·정확한 시각은 보내지도 저장하지도 않는다. 서버는 받은 날짜만 일 단위(UTC)로 남긴다. `sid`는 결과마다 브라우저가 새로 만든 무작위 값으로 같은 결과를 두 번 보내는 것만 막는다.
- 참여는 기본값. 인지 검사 결과를 처음 볼 때 한 번 안내(`.stats-notice`)와 스위치가 나오고, 안내 페이지(`#/about`)에서도 끌 수 있다(localStorage `bl.stats.share`가 `false`면 참여 안 함). 보내기는 큐(`bl.stats.queue`)에 넣어 결과 화면에서(첫 안내가 보일 때는 끌 시간을 주려고 8초 뒤, 화면을 먼저 떠나면 그때) 또는 다음 방문 때 보내고, 실패(429·5xx)하면 큐에 남긴다. 종합 프로필·미리보기는 보내지 않는다. `js/config.js`의 `statsUrl`이 비어 있으면 모든 기능이 꺼지고 안내·스위치도 나오지 않는다.
- 서버(`server/src/index.js`): `POST /submit`(모양·범위 검증 뒤 저장, 본문 16KB 제한, `ALLOWED_ORIGINS`의 Origin만, IP당 60초 20회), `GET /stats`(집계), `GET /export`(원자료, `Authorization: Bearer <ADMIN_TOKEN>`, 토큰을 안 넣었으면 404), `GET /`(받은 결과 수·집계 시각). GET도 IP당 60초 60회. 빈도 제한은 Cloudflare의 `ratelimits` 바인딩(순간 계수기)이라 IP가 어디에도 남지 않는다. 표(`server/schema.sql`): `submissions`(결과 하나, payload JSON)·`task_rows`(과제 하나씩, 집계용)·`stats_cache`(집계 한 벌). Workers 로그 저장(`observability`)은 꺼 두어 요청 정보가 Cloudflare에 남지 않는다(실시간 확인은 `npx wrangler tail`). 모르는 필드는 버린다(예: 정확한 시각을 보내도 저장 안 됨). Cloudflare의 IP 빈도 제한은 엣지마다 따로 세는 느슨한 제한이라(배포 뒤 시험: 60건을 한꺼번에 보내면 1건만 막힘), 서버 전체 전송 상한을 하나 더 둔다: 분당 `MAX_PER_MIN`(60)·하루 `MAX_PER_DAY`(3000)건, D1 `quota` 표에 개수만 센다(IP 없음). 넘치면 429이고 사이트는 큐에 남겼다가 다시 보낸다(시험: 1분에 75건 → 60건 저장, 15건 429).
- 집계는 계산해서 `stats_cache`에 담아 두고 1시간마다(표본이 60명 미만이면 1분마다) 다시 계산한다. workers.dev 주소에서는 Cache API가 동작하지 않고, 요청마다 계산하면 D1 무료 읽기 한도(하루 500만 행)를 금방 쓰기 때문이다. 한 번 계산에 최근 결과 1만 개(`MAX_ROWS`)까지 읽어 하루 최대 약 250만 행이다. `?fresh=1`은 `ADMIN_TOKEN`을 함께 보낼 때만 바로 다시 계산한다.
- 집계 내용: 과제별 응시자 수, 과제 z의 평균·표준편차·백분위(0~100, 101개 값; 표본이 `MIN_SAMPLE`=30 미만이면 `q: null`), 정답률 과제는 단계별 문항·정답 수(정밀 검사 응답은 `nFull`·`cFull`로 따로)와 응시자별 정답률 분포, 폭·개수 과제는 값별 인원, 반응 시간은 중앙값의 평균·표준편차(전체·마우스·터치)와 분포, 종합 z는 모드(adaptive·quick·full)별 백분위. 표준 시간(`time_factor` 1)으로 푼 결과만 집계하고 나머지는 `excludedNonStandardTime`으로 센다. 문항 기록이 있으면 단계별 시간 초과 수(`miss`)·평균 응답 시간(`t`, 초)과 언어 풀 문항별 정답률(`pool`)도 낸다. 입력 방식별 인원은 `device`.
- 결과 화면(`mountStats`): 집계가 오고 그 분포의 표본이 30명 이상이면 배지 아래에 "실제 응시자 n명 기준 상위 %"(모드별 종합 분포, 과제별 검사는 그 과제 분포), 과제 막대 옆에 "실제 상위 % (n명)"가 붙는다. 30명 미만이면 아무것도 나오지 않는다. 종합 프로필은 과제별로만 비교한다. 백분위는 같은 값을 가운데 등수로 세고 1~99%로 자른다. 기준값이 실제 자료로 보정된 판이면(버전 이름 `data-<날짜>-n<명>`) 배지 아래에 "기준값 · 응시자 N명 자료 반영"이 붙는다. 설계값·AI 추정값(`design-…`·`ai-est-…`)이면 붙지 않는다.

배포(처음 한 번, `server` 폴더에서). Cloudflare 무료 계정이 필요하고 로그인(`wrangler login`)은 사용자가 직접 승인한다. 비밀 값은 저장소에 넣지 않는다:

```
cd server
npm install
npx wrangler login
npx wrangler d1 create brainlab-stats
```

출력된 `database_id`를 `server/wrangler.toml`의 `[[d1_databases]]`에 적은 뒤:

```
npx wrangler d1 execute brainlab-stats --remote --file=schema.sql
npx wrangler deploy
```

`https://brainlab-stats.<계정>.workers.dev` 주소가 나오면 `js/config.js`의 `statsUrl`에 넣고 커밋·push 한다. 서버 코드를 고치면 `npx wrangler deploy`만 다시 한다. 원자료를 받으려면 `npx wrangler secret put ADMIN_TOKEN`으로 토큰을 넣는다(저장소에는 두지 않는다. `.dev.vars`·`.wrangler/`는 gitignore). PowerShell에서 `토큰 | npx wrangler secret put`으로 넘기면 줄바꿈 문자가 값에 섞이니, `{"ADMIN_TOKEN":"…"}` 파일을 만들어 `npx wrangler secret bulk 파일`로 넣고 파일은 지운다.

운영:

- 상태: `/` → 받은 결과 수(지운 것 포함)와 집계 표본 수, `/stats` → 집계, `npx wrangler tail` → 실시간 로그.

- 기준값 보정: `node tools/norms-from-stats.cjs https://brainlab-stats.<계정>.workers.dev` → 바뀌는 값, 새 `LEVEL_P`·`NORMS` 블록, 실제 정답률이 단계의 기대 정답률과 0.15 넘게 어긋나는 언어 문항(30회 이상 푼 것)을 보여 준다. 자료가 수백 명 쌓이기 전에는 지금 값(설계값·AI 추정값)을 그대로 쓴다: `--write`는 표본이 300명(`--min-people`) 이상일 때만 `js/tests/cognitive.js`에 쓰고(시험용은 `--force`), `NORMS_VERSION`을 `data-<날짜>-n<표본>`으로 올려 결과 화면에 "응시자 N명 자료 반영"이 나오게 한다. 도구는 `tools/cognitive-model.cjs`로 `cognitive.js`를 직접 읽어 지금 `LEVEL_P`, 언어 풀 문항의 지금 단계, 과제별 보기 수를 쓴다. 규칙: `LEVEL_P`는 찍기 몫을 뺀 값이라 관측 정답률 q를 (q − c)/(1 − c)(c = 1/보기 수: 행렬 1/8, 도형 유추 1/6, 나머지 1/4)로 바꿔 넣는다. 집단 평균 정답률을 θ = 0인 사람의 값으로 보는 근사라, 가상 응시자 1500명으로 시험하면 참값과 평균 −0.006·최대 0.06 차이로 되찾고 쉬운 단계는 조금 낮게·어려운 단계는 조금 높게 나온다(바꾸기 전 식은 평균 +0.089로 모든 단계를 쉽게 적었다). 생성 문항 과제는 정밀 검사 응답이 단계마다 100개(`--min-items`) 이상이면 그 값, 아니면 적응형을 합친 값(그 단계에 도달한 사람만 푸니 치우침이 있어 출력에 `~`로 표시), 그것도 모자라면 지금 값을 둔다. 언어 4과제는 문항별 자료(`pool`)를 지금 단계로 다시 묶어 쓴다(모드 합침, `~문항` 표시, 풀에 없는 번호는 뺌). 단계별 기대 관측 정답률 c + (1 − c)·`LEVEL_P`와 0.15 넘게 어긋나는 언어 문항도 이 식으로 판정한다. 단계가 오를수록 내려가게 다듬고(인접 위반 합치기) 0.05~0.97로 자른다. 폭·개수·반응 시간은 응시자 30명(`--min`) 이상이면 평균·표준편차(반응 시간은 마우스 응시자 우선, 모자라면 터치 몫 30ms×터치 비율을 뺀 전체). `OBS`(영역·종합 규준화)는 바꾸지 않고 참고 수치(z 표준편차·정답률 과제 z 평균)만 찍는다. 상관(within·between)은 `/export` 원자료에서 따로 구해야 한다. 쓴 뒤에는 `NORMS` 위 주석("임시 기준값")과 이 README "검사 구성"의 기준값 설명을 손본다.
- 가짜 자료를 지운 뒤에 보정한다. 옛 기준값으로 낸 z도 집계에 섞이지만 원점수(정답 수·폭·반응 시간)는 그대로라 보정 자체에는 문제없고, 백분위 비교만 조금 흐려진다. 언어 4과제는 2026-10-18 단계 재조정 전 자료의 단계 라벨(`levels`)이 지금과 달라서, 도구는 언어 과제에 `levels`를 쓰지 않고 문항 번호로 지금 단계를 찾는다(풀은 뒤에만 붙이므로 번호가 그대로다). 보정 뒤 쌓인 자료만 쓰려면 `/export`에서 `norms`로 걸러 낸다.
