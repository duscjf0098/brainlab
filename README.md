# 두뇌실험실

인지 능력, 정서 지능, 성격, 연애 애착 유형, 연애 스타일, 진로 흥미 유형을 측정하는 자기평가 웹사이트. 서버 없이 정적 파일만으로 동작한다.

## 실행

```
node serve.cjs
```

브라우저에서 http://localhost:5173 을 연다. `index.html`을 더블클릭해도 동작한다.

## 구조

- `index.html` 진입점. 스크립트 로드 순서가 중요하다 (util → tests → card → app).
- `css/style.css` 밝고 부드러운 테마(2026-10-18, 크림 바탕·둥근 카드·알약 버튼). 색은 `:root` 토큰으로 관리한다. 사용자 결정으로 다크 모드 없이 항상 밝은 화면이다(`color-scheme: only light`, `<meta name="color-scheme" content="only light">`로 휴대폰·카카오톡 브라우저의 강제 어둡게도 막는다). 검사별 파스텔 색은 `.tint-<id>`(바탕·글자·강조·테두리)에 있고, `.tinted`를 붙인 화면은 그 색을 `--accent`로 써서 버튼·진행 막대·결과 막대가 검사 색을 따른다. 첫 화면 카드와 검사 소개의 질문형 제목은 `js/app.js`의 `LOOK`, 공유 이미지 색은 `js/card.js`의 `TINT`.
- 진행 화면(2026-10-18): 시간 제한이 없는 검사(정서 지능·성격·애착·진로 흥미·연애 스타일)는 "← 이전 문항"으로 돌아가 답을 바꿀 수 있고(전에 고른 답이 표시됨), 이미 답한 문항에서는 "다음 →"으로 넘어간다. 인지 검사는 제한 시간과 적응형 진행 때문에 되돌리기를 두지 않는다.
- `js/util.js` 난수(seeded RNG), HTML 이스케이프, 저장소 유틸.
- `js/stats.js` 익명 응시 통계: 인지 검사의 문항별 정답 여부·응답 시간과 과제별 원점수를 이름 없이 수집 서버에 보내고(끌 수 있음), 집계를 받아 결과 화면에 "실제 응시자 n명 기준 상위(가운데보다 아래면 하위) %"를 붙인다. 서버는 `server/`(Cloudflare Workers + D1), 기준값 생성은 `tools/norms-from-stats.cjs`. 자세한 것은 "익명 통계 서버".
- `js/tests/*.js` 검사 정의. 각 파일은 `BL.tests.<id> = { build(), score(answers, items), ... }` 를 등록한다. 검사 정의에 `related: [{ id, why }]`를 두면 결과 화면 맨 아래에 그 검사로 가는 "이어서 해 보기" 카드가 붙는다(애착 ↔ 연애 스타일).
- `js/card.js` 결과 카드 PNG 생성(1080×1350), 저장, 공유.
- `js/app.js` 해시 라우팅, 문항 렌더러(choice / likert / digitspan / reaction / section), 결과·기록·안내 화면.

## 라우트

- `#/` 홈
- `#/test/<id>` 소개 · `#/run/<id>` 진행 · `#/result/<id>/<n>` 결과
- `#/preview/<id>` 무작위 응답으로 결과 화면만 미리보기 (디자인 작업용). 인지 검사는 `#/preview/cognitive/quick` 으로 빠른 검사 결과도 볼 수 있다.
- `#/history` 내 기록 · `#/about` 안내
- 돌려보내는 이동(2026-11-13): 모르는 주소, 세션 없는 진행 화면, 없는 결과 번호, 검사 끝 → 결과는 방문 기록을 쌓지 않고 지금 항목을 바꿔 끼운다(`redirect()`: `history.replaceState` 뒤 `route()`, 막힌 환경이면 `location.replace`). 예전에는 결과에서 뒤로 가면 `#/run`으로 돌아갔다가 다시 소개로 넘겨져서 뒤로 가기로는 사이트를 빠져나갈 수 없었다. 지금은 결과 → 소개 → 그 앞 화면 순으로 나간다. 주소의 검사 id는 `has()`(자기 속성인지)로 확인해서 `#/test/constructor` 같은 주소가 화면을 깨지 않는다.

검사 id: `cognitive`, `eq`, `personality`, `attachment`, `interest`, `love` (홈 카드 순서)

## 접근성과 입력 (2026-11-13)

- 제목과 초점: 화면이 바뀌면 문서 제목을 "<그 화면의 h1, 40자까지> — 두뇌실험실"로 바꾸고(홈은 `index.html`의 원래 제목), 초점을 읽기 시작점으로 옮긴다(`setScreen`). 검사 화면은 문항의 첫 글(안내 카드 제목·상황 글·질문), 그 밖의 화면은 h1이다(`tabindex="-1"`, 스크롤은 건드리지 않고 테두리는 그리지 않음). 처음 연 화면은 옮기지 않는다. 검사 화면에는 화면 낭독기만 읽는 h1(`.sr-only`, 검사 이름)이 있다. 숫자 키 단축키는 `document`에서 받아서 초점 위치와 상관없이 듣는다. 결과 화면에 안내 띠(저장 실패, 종합 프로필, 미리보기)가 있으면 h1 대신 그 띠로, 연습 문항은 "연습 문제 · 점수에 안 들어가요" 표시로 옮겨 그 글부터 읽게 한다. 같은 문항 안에서 화면이 바뀌는 곳 가운데 기억 폭 과제의 답 넣기 화면(`spanInput`)과 연습 피드백 상자(`role="status"`, 결과 글로 초점)는 따로 초점을 옮긴다. 결과 화면의 탭 제목은 h1(점수·유형) 대신 "결과 · <검사 이름>"으로, 종합 프로필은 "종합 프로필 · <검사 이름>", 미리보기는 "미리보기 · <검사 이름>"으로 쓴다(점수가 브라우저 방문 기록·탭 목록·화면 공유에 남지 않게).
- 역할과 이름: 진행 막대 `role="progressbar"`(값 = 끝낸 문항 수), 남은 시간 줄 `role="timer"`, 고른 보기·리커트 칸·시간 설정 칸에 `aria-pressed`, 리커트 다섯 칸은 문항 글을 이름으로 한 `role="group"`, 그림 보기 버튼은 "보기 N"(그림이 `aria-hidden`이라 이름이 비어 있었다). 그림 보기의 연습 피드백은 "정답은 초록 테두리로 표시한 N번째 보기예요"로 색과 순서를 함께 말한다. 접힌 목록의 "펼치기/접기"·화살표 글자는 꾸밈이라 화면 낭독기가 읽지 않게 했다(`content: "…" / ""`).
- 누르는 곳은 높이 44px 이상: 상단 메뉴, "전체 보기" 같은 링크, "← 실험 목록", 시간 설정, 과제 칩, 이전/다음, 익명 통계 스위치, 세부 펼치기. 글자 자리와 화면 길이가 바뀌지 않게 위아래 음수 여백으로 누르는 범위만 넓혔다.
- 대비: 흐린 글자 `--muted`는 #675c55(크림 바탕 6.2:1, 파스텔 틴트 위 5.4~5.7:1. 예전 #7a6e67은 틴트 위 4.1~4.4:1). 틴트 위의 작은 머리글·배너·연습 표시는 틴트 글자색, 결과 막대의 숫자도 틴트 글자색, 세부 막대는 강조색으로 채운다(예전에는 막대 바탕과 1.2~1.4:1이라 거의 안 보였다). 색-단어 간섭 버튼의 숫자(키보드 1~4 안내)는 주황·보라·초록 버튼에서 3.1~3.9:1로 남아 있다(버튼 색은 색각 이상을 고려해 고른 값이라 그대로 두고 굵기·그림자만 줬다. 색 이름은 `aria-label`에 있다).
- 동작 줄이기(`prefers-reduced-motion: reduce`)를 켠 기기에서는 문항이 떠오르는 효과, 막대가 차오르는 효과, 남은 10초 숫자 깜빡임, 부드럽게 굴리기를 끈다. 남은 시간 막대는 그 자체가 정보라 그대로 둔다.
- 키보드: 단순 반응은 스페이스·엔터로도 누를 수 있다(누르고 있기는 무시, 입력 방식 '키보드'로 기록. 시작 카드에 "PC에서는 스페이스 바를 눌러도 돼요"). 숫자-문자 순서는 숫자 키 1~9를 받고, 이미 넣은 키는 `disabled` 대신 `aria-disabled`와 `.used`(흐리게)로 표시해 초점이 떨어지지 않는다. 기억 폭 입력의 Enter는 다 채웠으면 확인, 덜 채웠고 초점이 칸·키패드 버튼에 있으면 그 버튼 누르기다. 초점이 "하나 지우기"에 있으면 Enter는 늘 지우기다(다 채운 뒤 고치려다 그대로 제출되던 것을 고침). 기억 폭 연습 결과와 답 넣기 화면도 초점을 옮긴다(연습이면 "연습 · 점수에 안 들어가요" 표시부터).
- 그린 직후 300ms 입력 막기(`READY_MS`): 객관식·리커트의 고르기(숫자 키 포함)와 안내·파트·연습 카드의 시작·다음 버튼은 그린 지 300ms 안의 입력을 받지 않는다. 폰에서 빠르게 두 번 탭하면 두 번째 탭이 방금 새로 그린 다음 문항의 같은 자리에 들어가, 보지도 않은 문항에 답이 들어가던 것을 막는다. 숫자 키를 누르고 있을 때의 자동 반복도 객관식·리커트에서 답으로 치지 않는다(문항이 줄줄이 넘어갔다). 그림 보기에는 번호를 그리지 않는다(숫자 키는 왼쪽 위부터 1~8).
- 저장소에서 읽은 값: 결과의 다시 보기 그림과 애착 좌표 그림은 마크업째 `localStorage`에 있어서, 화면에 넣기 전에 `U.safeFig`로 거른다(허용한 SVG·글 태그만 남기고 속성은 `U.figAttrOk`로 거른다: 실제 그림이 쓰는 속성 이름만(on*·href·src·tabindex·cursor·mask 등은 이름에서 걸림), class는 그림이 쓰는 이름뿐일 때만, style은 `--w:143` 같은 숫자 변수뿐일 때만, `url(`은 문서 안 참조 `url(#id)`만, id는 clipPath의 `clipN`만, width·height는 네모(rect)에만 남기며 역슬래시가 든 값은 지운다. 스크립트 실행뿐 아니라 바깥 주소 불러오기, 사이트 CSS의 class나 style로 화면 덮기, 저장 버튼 id 가로채기도 막는다). 점수 값은 이스케이프한다. 그림에 새 태그·속성·class를 쓰면 `js/util.js`의 `FIG_TAGS`·`FIG_ATTRS`·`FIG_CLASSES`에 넣어야 결과 화면에서 사라지지 않는다(`node .claude/checks/figtags.cjs "$PWD"`로 확인. 2026-11-14에 지난 커밋 34개 판의 그림도 이 규칙에서 지워지는 것이 없음을 확인). 결과 목록에 깨진 항목(객체가 아니거나 검사 id가 문자열이 아닌 것)이 섞여도 홈·내 기록이 깨지지 않고(`results()`가 거름), 저장 시각이 없는 옛 결과는 날짜 없이 보여 주며 지울 수 있다.

## 글 톤과 설명 블록

- 사용자에게 보이는 설명은 쉬운 말, 해요체로 쓴다(문항·정답 해설은 제외). 전문 용어는 꼭 필요할 때 한 번만 쓰고 바로 풀어 준다.
- 영역·갈래·축마다 `what`(무엇을 재나)과 `where`(일상에서 어디에 쓰이고 어떤 영향을 주나)를 둔다. 각 검사 객체의 `explain` 배열이 **결과 화면**의 "무엇을 잰 걸까요, 어디에 쓰일까요" 블록이 된다(소개 페이지에는 두지 않는다; 결과에 나온 영역만 표시). 인지 과제 20개는 `TASKS[k].where`가 과제 시작 카드에 "일상에서" 줄로 나온다.

## 문항 갤러리 (검수용)

- `#/gallery/<과제 키>/<단계 또는 all>[/<단계당 개수>]` — 예: `#/gallery/matrix/all`, `#/gallery/weights/5/3`. 생성 문항을 연습 모드(타이머 없음)로 쭉 그려 주고 정답 보기를 초록 테두리로 표시한다. 저장되지 않는다. 로컬 개발(주소가 `localhost`·`127.0.0.1`)에서만 열리고 공개 사이트·아티팩트에서는 홈으로 돌려보낸다(2026-11-13. 공개 사이트에서 언어 과제 고정 문항의 정답을 다 볼 수 있으면 익명 통계의 기준값 보정이 오염될 수 있다. `index.html`을 더블클릭해 연 `file://`에서도 열리지 않으니 `node serve.cjs`로 띄운다). 과제 키: matrix, figAnalogy, series, sequence, weights, rotation, fold, blocks (analogy·vocab·logic·similar도 됨).

## 법적 메모

- 도형 행렬과 수열 문항은 규칙 기반으로 매번 생성되는 원본 문항이다. 전개도 접기·블록 세기도 규칙으로 매번 새로 그린다(정육면체 전개도 11가지는 도형의 성질이고, 무늬와 그림은 직접 만들었다).
- 성격 검사 문항은 공개 도메인인 IPIP 항목을 바탕으로 번역·각색한 것이다.
- 도형 문항의 오답은 속성별로 값이 고르게 나오도록 만들어, 문제를 보지 않고 보기만 비교해서는 정답을 고를 수 없다. 정서 지능 보기는 길이를 비슷하게 맞췄다.
- 정서 지능, 애착, 연애 스타일 문항은 이 사이트를 위해 직접 썼다. 연애 스타일은 존 리의 이론(개념)만 빌렸고 Hendrick의 사랑 태도 척도(LAS) 문항은 옮기지 않았다.
- 진로 흥미 문항도 이 사이트를 위해 직접 썼고, 홀랜드의 여섯 유형 이론(개념)만 빌렸다. 공개 흥미 문항 모음(IIP)의 기초 흥미 척도(BIM, Liao·Armstrong·Rounds 2008)는 저자 저작권이 있고 전문가의 비상업적 사용만 무료로 허락되어 있어(2026-10-18 WSU 연구실 페이지 확인) 쓰지 않았다. RIASEC 마커는 O*NET 흥미 검사 문항에서 나온 것이라 역시 쓰지 않았고, 워크넷 직업흥미검사 문항도 옮기지 않았다. 결과의 직업은 예시로만 보여 주고, 흥미는 적성·능력과 다르다는 안내를 모든 결과에 붙인다.
- 모든 결과 화면에 "참고용 자기평가" 면책 문구가 붙는다. IQ 숫자나 진단 표현은 쓰지 않는다.
- 개인정보를 받지 않으며 결과는 localStorage에만 저장된다. 인지 검사의 문항별 정답 여부(문항 내용이 아니라 번호)·응답 시간과 과제별 원점수만 익명 통계로 보낼 수 있고(기본 참여, 첫 결과 화면과 안내 페이지에서 끌 수 있음), 서버에도 이름·연락처·IP·기기 식별자·정확한 시각을 저장하지 않는다("익명 통계 서버"). 문항 자체는 바꾸지 않았다.

## 익명 통계 서버 (server/)

인지 검사의 임시 기준값(`NORMS`·`LEVEL_P`)을 실제 응시 자료로 보정하기 위해, 2026-10-18부터 결과의 과제별 원점수를 익명으로 모은다. 정적 사이트는 그대로 GitHub Pages에 있고, 수집 서버만 Cloudflare Workers + D1에 둔다(무료 티어: 하루 요청 10만 건, D1 읽기 500만·쓰기 10만 행, 저장 5GB. 이 사이트 규모에는 충분하다).

- 보내는 것(`js/stats.js`, 인지 검사만): 검사 id, 모드, 시간 설정, 입력 방식(터치/마우스, `pointer: coarse`), 기준값 버전(`NORMS_VERSION`), 종합 z, 과제별 { z, 정답 수·문항 수, 단계별 정답 수(`levels`), 적응형 여부, 문항마다 `[풀 번호, 단계, 정답 1·오답 0·시간 초과 -1, 응답 시간(0.1초)]`(`items`), 기억 폭(2026-10-18부터 부분 점수 `part`·다시 시작 횟수도 붙지만 서버는 아직 최장 폭만 저장), 반응 시간 중앙값, 정확도, 터치 여부 }. 2026-10-18부터 반응·기호 찾기 과제에는 일찍 누름·너무 빠름·너무 늦음·다시 시작·화면 벗어남 횟수, 입력 방식(터치·마우스·키보드), 감점 전 중앙값·간섭값도 붙는다(서버가 아직 저장하지 않는 필드는 서버가 버린다). 정확도가 찍기 수준이라 "측정 안 됨"인 과제는 보내지 않는다. 원점수는 `cognitive.js`의 `taskStats`가 `tasks[k].obs`에 넣는다(z 계산 전 값). 풀 번호는 언어 4과제의 고정 문항 풀 번호(`choiceItems`가 붙이는 `pid`, 풀은 뒤에만 붙이므로 번호가 바뀌지 않는다)이고, 그때그때 만드는 도형·숫자 문항은 -1과 단계만 보낸다. 문항 내용, 이름·이메일·IP·User-Agent·기기 식별자·정확한 시각은 보내지도 저장하지도 않는다. 서버는 받은 날짜만 일 단위(UTC)로 남긴다. `sid`는 결과마다 브라우저가 새로 만든 무작위 값으로 같은 결과를 두 번 보내는 것만 막는다.
- 참여는 기본값. 인지 검사 결과를 처음 볼 때 한 번 안내(`.stats-notice`)와 스위치가 나오고, 안내 페이지(`#/about`)에서도 끌 수 있다(localStorage `bl.stats.share`가 `false`면 참여 안 함). 보내기는 큐(`bl.stats.queue`)에 넣어 결과 화면에서(첫 안내가 보일 때는 끌 시간을 주려고 8초 뒤. 안내가 없는 결과 화면은 바로, 그 화면을 먼저 떠나면 떠날 때) 또는 다음 방문 때 보내고, 실패(429·5xx·네트워크)하면 큐에 남긴다. 2026-11-13 손봄: 첫 안내가 보인 화면을 8초 안에 떠나면 그때 보내지 않고(안내 페이지에서 끌 수도 있으니) 다음 결과 화면이나 다음 방문 때 보낸다. 큐는 보내기 전에 비우지 않고 보낸 것(또는 400·403·413처럼 다시 보내도 같은 것)만 하나씩 지워서, 보내는 도중에 창을 닫아도 남은 결과가 사라지지 않는다. 끌 때는 큐를 먼저 지운 뒤 꺼짐을 저장하고, 저장 공간이 꽉 차 꺼짐을 저장하지 못하면 그 탭에서만 꺼 두고(sessionStorage) 스위치 아래에 그렇게 알린다. 결과 화면을 떠난 뒤 늦게 온 집계 응답은 버린다(다른 결과 화면에 앞 결과의 값이 들어가지 않게). 종합 프로필·미리보기는 보내지 않는다. `js/config.js`의 `statsUrl`이 비어 있으면 모든 기능이 꺼지고 안내·스위치도 나오지 않는다.
- 서버(`server/src/index.js`): `POST /submit`(모양·범위·값끼리 검증 뒤 저장(아래 "입력 검증"), 본문 16KB 제한, `ALLOWED_ORIGINS`의 Origin만(2026-11-14부터 Origin 머리글이 없는 요청도 403), IP당 60초 20회), `GET /stats`(집계), `GET /export`(원자료, `Authorization: Bearer <ADMIN_TOKEN>`, 토큰을 안 넣었으면 404), `GET /`(받은 결과 수·집계 시각). GET도 IP당 60초 60회. 빈도 제한은 Cloudflare의 `ratelimits` 바인딩(순간 계수기)이라 IP가 어디에도 남지 않는다. 표(`server/schema.sql`): `submissions`(결과 하나, payload JSON)·`task_rows`(과제 하나씩, 집계용)·`stats_cache`(집계 한 벌). Workers 로그 저장(`observability`)은 꺼 두어 요청 정보가 Cloudflare에 남지 않는다(실시간 확인은 `npx wrangler tail`). 모르는 필드는 버린다(예: 정확한 시각을 보내도 저장 안 됨). Cloudflare의 IP 빈도 제한은 엣지마다 따로 세는 느슨한 제한이라(배포 뒤 시험: 60건을 한꺼번에 보내면 1건만 막힘), 서버 전체 전송 상한을 하나 더 둔다: 분당 `MAX_PER_MIN`(60)·하루 `MAX_PER_DAY`(3000)건, D1 `quota` 표에 개수만 센다(IP 없음). 2026-11-14부터 검증과 중복 확인을 통과한 결과만 센다(예전에는 맨 앞에서 세서 잘못된 요청·중복 요청도 하루 상한을 썼고, 한 사람이 상한을 다 쓰면 그날 실제 응시자의 전송이 모두 429가 될 수 있었다). 넘치면 429이고 사이트는 큐에 남겼다가 다시 보낸다(시험: 1분에 75건 → 60건 저장, 15건 429).
- 입력 검증(2026-11-14 보강, `validate`): 필드마다 모양·범위를 보고 모르는 필드는 버리는 것에 더해, 과제 z와 원점수가 서로 맞는지 본다. 사이트 채점이 낼 수 없는 조합은 조작으로 보고 결과 전체를 400(`inconsistent z <과제>`)으로 거절한다(사이트 큐는 400을 다시 보내지 않는다): 정답률 과제는 다 맞혔는데 z가 음수이거나 다 틀렸는데 양수, 폭 과제는 사이트와 같은 식으로 다시 낸 z(부분 점수 `part`가 있으면 `part`로, 없으면 최장 폭으로)와 1.5 넘게 차이, 반응 과제는 |z| > 1인데 z의 부호와 반응 시간이 반대(z가 양수면 기준보다 빨라야 한다. 터치는 기준 + 30ms), 기호 찾기는 (개수 − 평균)/표준편차와 1.5 넘게 차이. 폭 과제를 최장 폭으로만 견주면 두 번째 시도에서 맞힌 길이가 많은 정상 결과가 걸려서(가상 응시자의 폭 과제 10,940개 중 2개) `part`로 견준다(`part`는 견주는 데만 쓰고 저장하지 않는다). 종합 z는 과제 z 평균과 2 넘게 다르면 종합 z만 버리고(null) 과제 자료는 받는다. 사이트가 만드는 과제 구성(20과제·빠른 검사 7과제)에서는 과제 z를 어떻게 골라도 이 차이가 1.81 안쪽이다(사이트 채점 함수 `domainZ`·`overallZ`로 꼭짓점을 모두 세어 본 값). 문항 응답 시간이 0~6000(0.1초 단위 정수)이 아니면 그 값만 null로 받는다(예전에는 결과 전체를 400으로 거절해 그 결과의 다른 과제 자료까지 사라졌다). 서버에는 이 검사에 쓰는 사이트 기준값 사본(`NORM`·`SPAN_PART`·`TOUCH_MS`, 기준값 버전 `ai-est-2026-11-13`)이 있다. `js/tests/cognitive.js`의 폭·반응·기호 찾기 `NORMS`나 `SPAN_PART`·`TOUCH_MS`를 바꾸면(`tools/norms-from-stats.cjs --write` 포함) 서버 값도 같이 바꾸고 다시 배포한다. 평균이 표준편차의 절반쯤 움직이는 정도는 정상 결과가 걸리지 않지만, 크게 바뀐 채로 두면 정상 결과가 400으로 버려질 수 있다. 영역·종합 규준화 상수(`OBS`)를 바꾸면 종합 z 차이의 최대값을 다시 잰다(`.claude/checks/server-validate.cjs`). 한계: 원점수와 z를 함께 맞춘 조작(사이트 엔진을 그대로 돌린 가짜 결과, Origin 머리글을 직접 붙인 요청)은 막지 못한다. 그것까지 막으려면 백분위를 서버가 원점수로 다시 낸 값으로 계산해야 한다.
- 집계는 계산해서 `stats_cache`에 담아 두고 1시간마다(표본이 60명 미만이면 1분마다) 다시 계산한다. workers.dev 주소에서는 Cache API가 동작하지 않고, 요청마다 계산하면 D1 무료 읽기 한도(하루 500만 행)를 금방 쓰기 때문이다. 한 번 계산에 최근 결과 1만 개(`MAX_ROWS`)까지 읽어 하루 최대 약 250만 행이다. `?fresh=1`은 `ADMIN_TOKEN`을 함께 보낼 때만 바로 다시 계산한다.
- 집계 내용: 과제별 응시자 수, 과제 z의 평균·표준편차·백분위(0~100, 101개 값; 표본이 `MIN_SAMPLE`=30 미만이면 `q: null`), 정답률 과제는 단계별 문항·정답 수(정밀 검사 응답은 `nFull`·`cFull`로 따로)와 응시자별 정답률 분포, 폭·개수 과제는 값별 인원, 반응 시간은 중앙값의 평균·표준편차(전체·마우스·터치)와 분포, 종합 z는 모드(adaptive·quick·full)별 백분위. 표준 시간(`time_factor` 1)으로 푼 결과만 집계하고 나머지는 `excludedNonStandardTime`으로 센다. 문항 기록이 있으면 단계별 시간 초과 수(`miss`)·평균 응답 시간(`t`, 초)과 언어 풀 문항별 정답률(`pool`)도 낸다. 입력 방식별 인원은 `device`.
- 결과 화면(`mountStats`): 집계가 오고 그 분포의 표본이 30명 이상이면 배지 아래에 "실제 응시자 n명 기준 상위 %"(모드별 종합 분포, 과제별 검사는 그 과제 분포), 과제 막대 옆에 "실제 상위 % (n명)"가 붙는다. 가운데보다 아래면 "하위 n%"로 쓴다(2026-11-13, 임시 기준값 쪽 표기와 같은 규칙). 30명 미만이면 아무것도 나오지 않는다. 종합 프로필은 과제별로만 비교한다. 백분위는 같은 값을 가운데 등수로 세고 1~99%로 자른다. 기준값이 실제 자료로 보정된 판이면(버전 이름 `data-<날짜>-n<명>`) 배지 아래에 "기준값 · 응시자 N명 자료 반영"이 붙는다. 설계값·AI 추정값(`design-…`·`ai-est-…`)이면 붙지 않는다.

배포(처음 한 번, `server` 폴더에서). Cloudflare 무료 계정이 필요하고 로그인(`wrangler login`)은 사용자가 직접 승인한다. 비밀 값은 저장소에 넣지 않는다:

```
cd server
npm install
npx wrangler login
npx wrangler d1 create brainlab-stats
```

출력된 `database_id`를 `server/wrangler.toml`의 `[[d1_databases]]`에 적은 뒤:

```
npx wrangler d1 execute brainlab-stats --remote --file=schema.sql
npx wrangler deploy
```

`https://brainlab-stats.<계정>.workers.dev` 주소가 나오면 `js/config.js`의 `statsUrl`에 넣고 커밋·push 한다. 서버 코드를 고치면 `npx wrangler deploy`만 다시 한다. 원자료를 받으려면 `npx wrangler secret put ADMIN_TOKEN`으로 토큰을 넣는다(저장소에는 두지 않는다. `.dev.vars`·`.wrangler/`는 gitignore). PowerShell에서 `토큰 | npx wrangler secret put`으로 넘기면 줄바꿈 문자가 값에 섞이니, `{"ADMIN_TOKEN":"…"}` 파일을 만들어 `npx wrangler secret bulk 파일`로 넣고 파일은 지운다.

현재 배포(2026-10-18): `https://brainlab-stats.duscjf0098.workers.dev`, D1 `brainlab-stats`(APAC, id는 `wrangler.toml`), 계정 duscjf0098. 관리 토큰은 이 PC의 `server/.dev.vars`(gitignore)에만 있다. 배포 직후 가짜 결과와 시험 결과 247건으로 전송·집계·결과 화면 표시를 확인한 뒤 모두 지웠다(표 4개 비움, `sqlite_sequence` 초기화). 스키마를 바꿀 때는 `schema.sql`을 고치고 `--remote --command "CREATE TABLE IF NOT EXISTS …"`처럼 새 표·열만 따로 적용한다(`schema.sql` 전체를 다시 돌려도 `IF NOT EXISTS`라 안전하다).

- 기준값 보정: `node tools/norms-from-stats.cjs https://brainlab-stats.<계정>.workers.dev` → 바뀌는 값, 새 `LEVEL_P`·`NORMS` 블록, 실제 정답률이 단계의 기대 정답률과 0.15 넘게 어긋나는 언어 문항(30회 이상 푼 것)을 보여 준다. 자료가 수백 명 쌓이기 전에는 지금 값(설계값·AI 추정값)을 그대로 쓴다: `--write`는 표본이 300명(`--min-people`) 이상일 때만 `js/tests/cognitive.js`에 쓰고(시험용은 `--force`), `NORMS_VERSION`을 `data-<날짜>-n<표본>`으로 올려 결과 화면에 "응시자 N명 자료 반영"이 나오게 한다. 도구는 `tools/cognitive-model.cjs`로 `cognitive.js`를 직접 읽어 지금 `LEVEL_P`, 언어 풀 문항의 지금 단계, 과제별 보기 수를 쓴다. 규칙: `LEVEL_P`는 찍기 몫을 뺀 값이라 관측 정답률 q를 (q − c)/(1 − c)(c = 1/보기 수: 행렬 1/8, 도형 유추 1/6, 나머지 1/4)로 바꿔 넣는다. 집단 평균 정답률을 θ = 0인 사람의 값으로 보는 근사라, 가상 응시자 1500명으로 시험하면 참값과 평균 −0.006·최대 0.06 차이로 되찾고 쉬운 단계는 조금 낮게·어려운 단계는 조금 높게 나온다(바꾸기 전 식은 평균 +0.089로 모든 단계를 쉽게 적었다). 생성 문항 과제는 정밀 검사 응답이 단계마다 100개(`--min-items`) 이상이면 그 값, 아니면 적응형을 합친 값(그 단계에 도달한 사람만 푸니 치우침이 있어 출력에 `~`로 표시), 그것도 모자라면 지금 값을 둔다. 언어 4과제는 문항별 자료(`pool`)를 지금 단계로 다시 묶어 쓴다(모드 합침, `~문항` 표시, 풀에 없는 번호는 뺌). 단계별 기대 관측 정답률 c + (1 − c)·`LEVEL_P`와 0.15 넘게 어긋나는 언어 문항도 이 식으로 판정한다. 단계가 오를수록 내려가게 다듬고(인접 위반 합치기) 0.05~0.97로 자른다. 폭·개수는 응시자 30명(`--min`) 이상이면 평균·표준편차. 반응 시간은 몇 사람의 아주 느린 결과에 휘둘리지 않게 중앙값과 MAD×1.4826으로 잡는다(2026-10-18. 평균·표준편차는 참값 N(510, 80)에 딴짓 2%만 섞여도 580±568이 되고, 가짜 자료 800명 시험에서 예전 식은 단순 반응 290±40을 402±777, 선택 반응 470±80을 535±672로 적었다 → 지금 원자료 294±40·477±79, 집계 300±43·475±90). `/export` 원자료 JSON(`{ rows }`, 여러 쪽이면 배열)을 주면 정확도 0.85 미만(선택 반응·색-단어)과 너무 느린 결과(응시자 값이 단순 반응 1초·선택 반응 1.5초·색-단어 2.5초 초과)를 빼고, 터치 응시자가 30명 이상이면 터치 기준을 먼저 쓴다(평균 = 터치 중앙값 − `TOUCH_MS`, sd = 터치 MAD. 채점이 터치 응시자에게 `TOUCH_MS`를 더하므로 폰 응시자 중앙값이 그대로 기준). `TOUCH_MS`는 터치·비터치가 모두 30명 이상인 반응 과제의 중앙값 차의 중앙값으로 다시 어림해 `--write` 때 함께 쓴다. 원자료로 돌리면 정답률 과제는 표준 시간 결과만, 제한 시간이 없는 기억·속도 과제는 시간 설정과 상관없이 넣고 가짜 자료(`norms='fake-test'`)는 뺀다. `ai-est-2026-10-18b`에서 문항·절차가 바뀐 과제(회전·전개도·블록, 기억 폭 4과제, 반응 3과제)는 원자료에서 그 전 버전(`PROC_OLD`: `design-2026-10-18`·`ai-est-2026-10-18`)과 버전 없는 행을 빼고 몇 건 뺐는지 찍으며, 기호 찾기는 정확도 0.7 미만 행을 뺀다(지금 채점은 그런 판을 "측정 안 됨"으로 두고 보내지 않는다). `/stats` 집계로 돌리면 서버가 버전을 가리지 않고 합치므로 이 과제들이 있을 때 경고를 찍는다. `/stats` 집계만 주면 전체 백분위의 중앙값·사분위 범위/1.349에서 터치 몫(`TOUCH_MS`×터치 비율)을 빼고 경고를 찍는다. 반응 시간 sd가 지금 값의 1.5배 넘게 바뀌면 경고한다. `OBS`(영역·종합 규준화)는 바꾸지 않고 참고 수치(z 표준편차·정답률 과제 z 평균)만 찍는다. 상관(within·load)은 `/export` 원자료에서 따로 구해야 한다. 쓴 뒤에는 `NORMS` 위 주석("임시 기준값")과 이 README "검사 구성"의 기준값 설명을 손본다.
- 가짜 자료를 지운 뒤에 보정한다. 옛 기준값으로 낸 z도 집계에 섞이지만 원점수(정답 수·폭·반응 시간)는 그대로라 보정 자체에는 문제없고, 백분위 비교만 조금 흐려진다. 단, `ai-est-2026-10-18b`에서 문항·절차가 바뀐 과제는 원점수의 뜻도 달라져서 `/export` 원자료로 보정한다(도구가 옛 버전 행을 뺀다). 수열·저울은 `ai-est-2026-11-12`에서 오답 만드는 법이 바뀌어 찍기 정답률이 달라졌으므로, 이 두 과제는 `ai-est-2026-10-18b`까지의 행도 뺀다(도구의 `PROC_CHANGED`가 과제마다 빼는 버전 목록을 갖는다). `ai-est-2026-11-13`에서는 도형 행렬·도형 유추·도형 계열·수열·저울·회전·전개도의 문항·오답 만드는 법이 바뀌어, 이 일곱 과제는 `ai-est-2026-11-12`까지의 행을 모두 뺀다(`PROC_OLD3`). `ai-est-2026-11-14`에서는 도형 유추·회전의 보기 구성을 다시 짜서(위 "2026-11-14 도형 유추·회전 보기 다시 짜기") 이 두 과제는 `ai-est-2026-11-13`까지의 행도 뺀다(`PROC_OLD4`). 블록 세기와 기억·반응 과제는 `ai-est-2026-10-18b` 이후 행을 그대로 쓴다. 공통점 찾기는 2026-11-13에 문항 7개를 뒤에 덧붙였고(번호 47~53) 기존 번호는 그대로다. 언어 4과제는 2026-10-18 단계 재조정 전 자료의 단계 라벨(`levels`)이 지금과 달라서, 도구는 언어 과제에 `levels`를 쓰지 않고 문항 번호로 지금 단계를 찾는다(풀은 뒤에만 붙이므로 번호가 그대로다). 보정 뒤 쌓인 자료만 쓰려면 `/export`에서 `norms`로 걸러 낸다.
